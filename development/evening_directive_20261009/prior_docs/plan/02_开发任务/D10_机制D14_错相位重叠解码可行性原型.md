# D10 机制 D14：两路错相位重叠解码——可行性原型（**高风险**）

| 项 | 值 |
|---|---|
| 优先级 | P3（只做可行性；立项完整实现要等本卡结论 + 总负责人批准） |
| 估计 | 本卡 3–5 人日（完整实现读码估计 10–20 人日，论文附录 D） |
| 基点 | `exp/e1-ms`（含 D02 时间线） |
| 依赖 | **T05（E1-R005）子项 e 的时间线**（每层搬运/计算、可重叠比例、气泡）；没有 T05 数据不开工 |
| 01 验证 | 原型不进服务路径，不需要 T16；结论由总负责人决定是否建 01 卡 |
| 风险等级 | **高**：图契约（整步一张 CUDA Graph）、两路拷贝流排队、气泡、PCIe 占满后预填几乎无余量 |
| 论文依据 | v3.2 §4.4 (3)（串行 43.4 ms / 约 23 tok/s；错相位理想 24.0–28.2 ms / 约 35–42 tok/s，**由旧系数得到的理想情景，不是实测、置信区间或已证明的硬上界**；四条假设）；§7.5；§4.6 表「两会话同时解码，每路 > 30：未测，有条件的候选路径」 |

## 目标

回答一个问题：**在本机上，把两路解码按层错开、让一路的缺失拷贝与另一路的计算重叠，实测能把两路步长从串行降多少？** 只做独立原型，不接入服务。

## 范围

- 独立脚本 `scripts/proto_d14_overlap.py`（远端运行，占 GPU，需按规则 §6 过门、拿锁；开发自检工件写 `/data2/FreeToken/runs/dev_D10/`）：
  - 加载**真实**一层或若干层的专家权重与缓存布局（复用 FreeToken 的模块，不改其代码），用 T05 时间线中的缺失数分布构造两路解码的每层「缺失拷贝 + 计算」负载；
  - 三种执行结构对比：(1) 串行（同流，复现 §4.4 串行行）；(2) 两路各自成图、两条流交错发射；(3) 按层拆图、拷贝流统一排队；
  - 记录每步墙钟、PCIe 占用率、气泡。
- 输出：三种结构的步长中位数/P90、每路等效 tok/s、PCIe 占用率；与 §4.4 表三行对照（标「对照推算」）。

## 非目标

不改 `engine/graph.py`、不改调度器、不进入服务；不处理预填与解码的 PCIe 争用（§7.4 准入问题）。
