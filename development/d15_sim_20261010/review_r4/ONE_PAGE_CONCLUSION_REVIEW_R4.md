## 校准与口径

全局 LRU、raw-top-k 去重、hit-before-victim usage、`(usage,slot)` 受害者、每个
prefill 清空 `[0,1024)` 的独立回放，在四组均与 D0 精确一致（0.000000 pp）。

G_two 必须分开读：封存 D0 快照只覆盖 79 个完整步和第 80 步的层 0--10，故只用于
校准（42.617%）；策略正文使用完整 raw trace：85 decode 批、154 request token
（69 个 bs=2、16 个 bs=1），LRU 基线为 42.590%。原方案的“70 个 bs=2”保留为历史
说法，不被本结果替换。

上下文中位数使用 UID 绑定的全 prompt + 先前 decode token、按 request token 加权：
seed12k/45k/real/two = 22.193/20.647/90.955/0.675 ktok。KIMI 的
0.768/1.395/2.127 是漏计 cached prefix，不再使用。

PA 网格只用 seed12k 选参，选择 `every=64, swaps=1`；45k/real/two 是留出结果。PA 是
8256553 中已接入 scheduler/adaptation boundary 的实现候选，仍缺 GPU 逐 token、D0、T21
验收。PA-lag1 是理论敏感性：假设 copy 在一步内完成；pending 槽在发布前失效时须丢弃，且
真实 AdaptationBoundary publish 后当次返回、不在同一 boundary 再排计划，因此不能把该列当作
0b 最终实现的测量。

P/PA/两种固定层策略的启动画像预置为 1,676 专家、4,646,676,480 B；PA e64/s1 的在线复制约
42 KB/步。Belady 同样给初始 1,676 槽未来最优预置，并允许 prefill 后保留任意 `S-1024`
对，因此是带免费未来信息的容量收缩上界，不能视作固定槽位精确最优或性能承诺。

容量是量级更大的杠杆：LRU 2700→3600 的 miss 分别降至 29.702/28.216/31.329/32.654%；
P@3600 只额外改善 0.022/0.022/0.061/0.495 pp。按 §4.7 常数
`13.1 + .032L + 5.3(B-1) + B(m*54.77 + swap_ms)` 折算，LRU@3600 B=1 为
33.25/34.23/30.15/32.25 tok/s；这是 CPU 模拟推导，尚非 GPU 性能证据。
