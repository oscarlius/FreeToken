## 3. 实现要点（与指令的对应）

- **A 会话**：payload 固定（§3.1）；非空增量口径与 A2 相同（`reasoning_content` 或 `content` 非空，`tool_calls` 单记）；收够 50 个增量才发第一个 B；每个 B 发出前检查 A 的运行时长，超过 300 秒则关闭旧 A、等 `/v1/stats` 的 `active` 归零、开新 A、再收够 50 个增量；B 结束后等 A 再收够 30 个增量。
- **事件**：T2 第 0–11 轮用任务 A 冻结的原样字节（先校验 INPUTS.json 的 SHA 与 messages）；L64 先校验原文件 SHA256 `261d50af…`，只把 `max_tokens` 从 2048 改为 32（代码会检查只有这一个字段变化）。L64 放在最后。
- **停顿 G**：A 在 `[t_d − 2, t_f + 2]` 内相邻两个非空增量之间的最大间隔。**零输出**：`(t_d + 0.4, t_f − 0.2)` 开区间内的非空增量数。
- **结构两级**：一级为 Prefill 行数等于段数；二级为一级成立，且每行 `new-token` 等于段长，首行 `cached-token` 等于预期、其余行为 0（与 window02 的生产日志一致）。
- **混入**：统计采样每 0.5 秒一次，`ours` 取读数前后我方在途数的较大者；`active > ours` 或事件前后 `completed` 差不等于我方完成数即为 contaminated；缺读数记为 unverified，不进入判读。
- **总判**：n 为进入判读且未混入、结构一级成立的事件数；k 为其中在区间内的个数；`k ≥ ceil(11n/13)` 成立，`k ≤ floor(6n/13)` 不成立，其余部分成立，`n < 9` 只报告。
- **停止规则**：监视线程每 5 秒查 `/health` 与 serve.log；不为 serving、OOM 文本、worker 退出标记，立即关闭全部我方连接并停止运行，不重试。总时限 15 分钟。

## 6. 演练中发现并修正的问题（如实记录）

1. **A 的运行时长有超出**：重启检查与 B 真正发出之间，原来还有一次 httpx 客户端的创建，且 B 的 t_d 记在创建之后。缩放 0.05 时，检查与发出之间的开销让运行时长超过阈值 0.13 秒。修正：整个运行只建一次 B 用的客户端；重启检查移到 `run_event` 中紧贴发出的位置。
2. **重启后的增量丢失**：`a_times.json` 原来只保存了最后一个 A 的增量，重启前的事件无法计算停顿与零输出。修正：保存并合并所有 A 会话的增量，并加单测覆盖。
3. **缩放失真**：零输出窗口起点 0.4 秒被缩放到 0.02 秒，比 HTTP 与线程的延迟还小，产生误报。修正：控制组也按真实时间（缩放 1.0）重跑。第一轮（缩放 0.05）的目录保留为 `rehearsal_attempt1_scale005`，不作为证据。
4. **单测断言**：假时钟里关闭与重开同一时刻，断言由 `<` 改为 `<=`（真实运行中两者之间有查询时间，严格小于仍成立）。
