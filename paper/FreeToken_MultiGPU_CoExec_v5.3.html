独立研究者

摘要

主存卸载的 MoE 推理把路由专家常驻主存，GPU 只缓存其中一小部分，其余专家一旦用到，就要经 PCIe 搬运。本文保留专家流遍数与 PCIe 时间预算的成本模型，并以新封存测量重写单卡正确性、容量和性能边界〔FTD-20261009-1〕。

本文的工作分三部分。

  1. 单卡实测。平台为一张 RTX 4090，模型为 Qwen3.8-Flash-Next NVFP4，路由专家 68.14 GB，常驻主存。
    • 层优先预填把冷 32K 的搬运从 8 遍减到 1 遍。叠加上游预填内核后，首 token 为 6.5–6.6 s，输出逐位一致。其中内核收益归上游。
    • 在两条真实 Agent 轨迹上，短后缀轮次的首 token 落在「一遍 ≈ 2.8 s」和「两遍 ≈ 5.6 s」两档，重算 token 数不足以解释这一差异。
    • 历史四格（FTD-20261003-1）显示：含未缓存锚点的首次请求被切成两段、多付一遍；其 warm 结果是后续 erratum hypothesis 的背景，不作当前质量或正确性验收。
    • K1 修复后的 T17 在七个尾段（65、4095、4096、4097、8191、8192、8193）取得 28/28 同结构 cold-reference 对照通过：四类状态、token 与全文逐位一致；它不证明所有可能的 ≥65 尾段。
  2. 成本模型。
    • 在当前失误率下，一遍预填的链路时间约等于 233 个解码 token 的未命中搬运（$L^{*}=E/(k\,m)$）。
    • 单卡链路给出的解码总量条件上界约为 $83(1-u)$ tok/s。
    • 解码目标改由串行模型与链路预算推出（§4.7），不再使用经验设定的每路 30 tok/s。以发布配置实测失误率 24.13% 计，单路 32K 理论值约 36.6 tok/s；两路在当前串行结构下每路约 21.8，理想错相位重叠与链路上界均约 37.8；8 路每路上界约 9.5。实测单路（≤ 64K）为所在结构理论值的 94–101%，两路为 103–105%；按 95% 判据只有一组单路 32K（93.9%）略低，87K 为 88%，未达到（§8.3）。
    • 推广到多卡：在每片只取一次的张量并行下，一遍的主存读字节与卡数无关，所以 $T_{pass}\ge P(1-h)/B_M$。在搬运受限、主存读带宽取本机交错参考值的条件下，卡数超过约 2 之后，这个下界不再随卡数下降；多卡收益可能主要来自驻留率上升（待测）。
  3. 协同执行方案。
    • 单卡机制：每轮只搬一遍、按遍合批准入、遍内插解码、两路错相位重叠解码、短后缀按需搬运。
    • 多卡组级执行器：按主存预算发放「遍令牌」、关键 rank 的缺失传输优先、按 G0 显存账选择 1×TP4 / 2×TP2 / 4×TP1。
    • 各机制的现状、代码挂点和验证协议见第 5 节。

证据边界：冷路径在绑定协议内可复现；同结构热/冷仅在已测尾段 ≥65 token 一致；≤64（含 1 token）走不写 checkpoint 分支，正确性待证；并发不保证相同输出〔FTD-20261009-1〕。多卡仍只有推导与方案。

Abstract

Host-memory-offloaded MoE inference keeps routed experts in DRAM and caches only a fraction on the GPU. This revision retains the expert-stream-pass and PCIe-budget model, but replaces obsolete state-resume claims with sealed v5 measurements〔FTD-20261009-1〕.

  • Layer-major prefill reduces a cold 32K prompt from 8 sweeps to 1.
  • Agent turns cluster at one-sweep (≈2.8 s) and two-sweep (≈5.6 s) tiers that token counts do not explain.
  • A paired cold/warm four-cell test ties the second sweep to anchor checkpointing on cold requests.
  • After K1 repair, T17 passes 28/28 same-structure cold-reference comparisons for four state classes, tokens, and text on measured tails 65–8193; this is not universal coverage.
  • Decode targets are now derived from the serial model and the link budget (§4.7) instead of a fixed 30 tok/s. At the measured release miss rate (24.13%), the single-stream 32K value is about 36.6 tok/s; two streams reach about 21.8 tok/s each under the current serial structure, with about 37.8 tok/s as the overlap and link ceiling. Measured single-stream rates (≤64K) are 94–101% of the structural value and two-stream rates 103–105%; by the 95% criterion only one 32K run (93.9%) falls slightly short, and 87K reaches 88%.

The three result classes are: reproducible cold paths under their bound protocol; consistent same-structure hot/cold paths only for the tested tails ≥65; and concurrency, which is not guaranteed to preserve output. Multi-GPU results remain analytical〔FTD-20261009-1〕.

1 引言

1.1 问题

开放权重的大型 MoE 模型已经可以在单机上运行，但其专家权重远超单卡显存。主存卸载是目前最直接的部署方式。FreeToken [1] 在这条路线上给出了一套完整的单机实现：主存专家池是唯一真相，GPU 上维护按（层，专家）整槽管理的 LRU 缓存；预填采用整层双缓冲；解码按测得的带宽，在 PCIe 搬运与 CPU 原地计算之间分配未命中专家。

我们的目标负载是约 10 个 Agent 会话：长上下文、多轮、带工具调用与思考段、中途编辑，常态 2–4 路同时生成，峰值 8 路。体验线如下：

  • 单会话 64K 窗口，首个有用 token ≤ 10 s。
  • 持续解码达到 §4.7 给出的理论值。v5.2 及以前使用的“每路 > 30 tok/s”是经验设定，没有模型依据；v5.3 起不再作为目标，只在 §4.7 中作为参考点，说明达到它需要什么条件。

在这种负载下，多个请求、多张卡争用同一组资源：主存读带宽、每卡的 PCIe 链路、CPU 核，以及（4090 不支持 P2P 时）经主存中转的集合通信。问题因此变为：如何安排专家的驻留、搬运和执行顺序，减少真正阻塞首 token 和后续 token 的等待。

1.2 立场：两个成本单位

原文已经指出：一次预填几乎激活全部专家，因而要把专家池完整搬运一遍（[1] §2.1）；在 PCIe 5.0 上，每个 8192 token 的预填块耗时恰好等于搬运一遍的时间（[1] §5.3）。「预填按遍计成本」这一现象不是本文的发现。本文研究它在服务层面的后果，并提出以下两个成本单位：

  • 专家流遍数：在当前整层加载路径下，短后缀请求的首 token 主要由「被切成几段」决定，而不是由「重算多少 token」决定。
  • PCIe 时间预算：预填的整池流与解码的未命中搬运共用每卡链路，多卡时还共用主存带宽。一遍预填与若干解码 token 之间存在可计算的换算关系。

2 背景与相关工作

2.1 继承自 FreeToken 的机制

  • 整层双缓冲预填：GPU 计算第 $l$ 层时，PCIe 搬运第 $l+1$ 层的全部专家。
  • 解码分流：某层有 $m$ 个未命中专家，每个 $S$ 字节，其中 $q$ 个搬进缓存，其余在 CPU 原地计算。原文 §3.2 把 $B_H$ 定义为测得的主机侧专家处理带宽，并假设 DMA 与 CPU 读同一个主存子系统，所以 PCIe 跑满时 CPU 只剩 $B_H-B_P$。令两路用时相等： $$\frac{qS}{B_P}=\frac{(m-q)S}{B_H-B_P}\ \Longrightarrow\ q^\star=m\,\frac{B_P}{B_H}.$$ $B_H$ 是实测处理率，不等于 STREAM。
  • 其他：语义锚点处的线性层状态检查点；可被 CUDA Graph 捕获的 LRU 缓存；弹性显存管理。

4 成本模型

4.1 专家流遍数 推导

一个预填段指一次完整的层循环。层优先时，第 $l+1$ 层的搬运与第 $l$ 层的计算重叠。一轮被切成 $J$ 段时：

$$T_{turn}\approx T_{queue}+\sum_{j=1}^{J}\Big[\max\!\Big(\frac{V_j}{B_P},\,C_j\Big)+\delta_j\Big]+T_{emit},$$

其中：

  • $V_j$ 为第 $j$ 段实际的 H2D 字节，整池时 $V_j\approx P(1-h)$。
  • $C_j$ 为该段的计算时间。
  • $\delta_j$ 为流水启停、层间不均匀造成的气泡等暴露成本，需用 trace 校准。

整池时，$P/B_P=2.80$ s，实测每遍 2.86 s。$C_j$ 低于搬运时，计算藏在搬运之后，本机对应约 16K token。

推论 1（按 token 切块的代价）　每多切一段，就多付一遍 $V_j/B_P$。冷 32K 按 4096 分块是 8 遍：推算约 22.9 s，实测 21.1–24.6 s〔第一代预填与解码基线〕。

推论 2（是否为保存状态多切一段）　在重叠模型下，同一遍内多算的 token，在计算超过搬运之前不增加时间。所以「为留检查点而多切一段」只在两种情况下划算：

  • 它让将来某一轮少付一遍。
  • 它省下的重算量足够大，使计算超过搬运。

4.2 冷预填 推导

层优先叠加 #578 后，每层计算约 131 ms，而每层搬运约 59 ms，冷预填受计算限制。$N$ 以千 token 计：

$$T(N)\approx 0.068N+0.107N+0.0002N^2+0.2\ \ \text{(s)},$$

其中第一项为 MoE（直接来自 诊断埋点 计时，2.22 s / 32.8K），后两项为非 MoE。

  • 32,064 token：推算 6.02 s，实测 6.07–6.60 s。
  • 65,412 token：推算 12.50 s，实测 12.43–14.08 s。

非 MoE 项由这两个点定出，自由度为 0，上面只说明拟合一致，不构成验证。留出点 8K、16K、48K 待测。在当前配置下，$T\le10$ s 的拟合阈值为 52.8K token。

4.3 解码（串行模型）推导

$$t_{step}(B,L)\approx t_0+kL+t_{req}(B-1)+B\,\frac{m\,S_{tok}}{BW}$$

参数为第 0 代拟合：$t_0=13.1$ ms，$k=0.032$ ms/千 token，$t_{req}=5.3$ ms。32K 单路推算 38 tok/s，实测 36.6–39.8 tok/s〔第一代预填与解码基线〕。

模型的假设：

  1. 传输与计算串行相加。这与当前实现相符：整步一张 CUDA Graph、批内同步，层内只有命中专家的计算能与缺失拷贝重叠。
  2. 路由独立且均匀。
  3. $m$ 不随会话数变化。
  4. $t_{req}$ 未分解到组件。

同提示并发会让各路路由几乎相同，从而高估多会话吞吐：同提示 2 路合计 63.34 tok/s〔硬件与带宽校准〕，不能当作多会话能力。

4.4 PCIe 时间预算 推导

一般形式：在同一窗口、同一链路的计量边界内，实际完成的 H2D 字节满足 $$V_{prefill}+V_{decode}+V_{other}\le\int_0^T B_{avail}(t)\,dt.$$

简化情景：带宽取常数 $B_P$，记 $\phi$ 为 CPU 原地计算的未命中比例： $$N_{pass}\frac{P(1-h)}{B_P}+N_{tok}\frac{m\,S_{tok}}{B_P}(1-\phi)\le T.$$ 由此得到三个量。

  1. 一遍等价的解码 token 数。 $$L^{*}=\frac{P}{m\,S_{tok}}=\frac{E}{k\,m}=\frac{512}{10\times0.2193}\approx233.$$ 一轮输出超过约 233 个 token 时，这一轮解码搬运所耗的链路时间，就超过它的一遍预填（图 3）。一般情形改用实测量： $$L^{*}_{traffic}=\frac{\text{一遍实测 H2D 字节}}{\text{每输出 token 平均实测 H2D 字节}}.$$
  2. 链路条件上界。 $$R_{max}=(1-u)\frac{B_P}{m\,S_{tok}}\approx83(1-u)\ \text{tok/s}.$$ 这是所有会话合计的必要条件。要满足峰值 8 路 × 30 tok/s，每 token 未命中字节需降到约 101 MB（失误率约 7.6%）。两路 × 30 tok/s 只需 17.5 GB/s，所以在 $u\le28\%$ 时，链路本身不排除这一目标。这两个数只说明链路条件；以 30 tok/s 为参考点的完整推算见 §4.7。
  3. 执行结构。两路、32K 时，按串行模型步长为 19.4 + 24.0 = 43.4 ms，每路约 23 tok/s。若两路错相位重叠（§5.3），理想步长为 24.0–28.2 ms，每路约 35–42 tok/s。这是用旧系数算出的情景，不是实测或上界；按发布配置失误率重算的值见 §4.7。

  • 一遍开始时收走所有已到达请求，至多 $c$ 个。

  1. 合批的价值在于稳定性。但「同一时刻合成一遍」上游已经实现（表 2），所以它不是本文的新机制。
  2. 合批把首 token 压住之后，预填遍会挤占解码的 PCIe 余量。λ=0.3 时，按简化情景，留给解码的合计约 30 tok/s。

4.6 推广到多 GPU：字节守恒与主存预算 推导

设 $n$ 张卡，每卡链路带宽为 $B_P$，组内共享可供 DMA 使用的主存读带宽 $B_M$。

命题 1（字节守恒）　前提：TP-$n$ 下每个专家切成 $n$ 片，每片只取一次；各卡的驻留比例相同，记为 $h$（不同时，用各卡中最慢的一张代替）；一遍处于搬运受限状态。那么一遍预填从主存读出的总字节仍是 $P(1-h)$，与 $n$ 无关。于是 $$T_{pass}^{(n)}\ \ge\ \max\!\Big(\frac{P(1-h)}{n\,B_P},\ \frac{P(1-h)}{B_M}\Big).$$

读法与适用范围：

  • 下界的拐点在 $n^\star=B_M/B_P$。$n<n^\star$ 时，卡数等分搬运确实有效：固定 $h$ 时，$n$ 从 1 到 2，下界从 2.80 s 降到约 1.46 s，降幅约 48%。
  • $n\ge n^\star$ 之后，下界由主存决定，约为 $P(1-h)/B_M$，不再随 $n$ 下降。
  • $n^\star$ 取决于 $B_M$ 的实际值，而 $B_M$ 又取决于专家池的放置方式。取本机交错 STREAM 参考值 46.6 GB/s 时 $n^\star\approx1.9$；若各卡都从本节点读取并接近 110.8 GB/s，则 $n^\star\approx4.6$。所以拐点必须在目标机上实测。
  • $h$ 本身随 $n$ 上升（§5.5）。在拐点之后，多卡收益可能主要来自驻留率，待测。
  • 冷长预填受计算限制时 $T_{pass}$ 不是约束，TP 的收益还包括分摊非 MoE 计算。
  • 解码的未命中搬运同理，下界为 $\max\big(mS_{tok}/(nB_P),\ mS_{tok}/B_M\big)$。

命题 2（数据并行时的遍令牌）　4×TP1 共享一个主存专家池时，若有 $k$ 条整池流同时进行：$k\,B_P\le B_M$ 时各流满速；超过时每条流降为约 $B_M/k$。四卡各存一份专家池不可行：4 × 68.14 GB = 272.6 GB（约 253.8 GiB），已略超约 251 GiB 的主存，再加 PLE 表（47.75 GiB）约 302 GiB，所以必须共享一个专家池。四卡同时冷预填约需 97 GB/s 的主存读带宽，是本机交错 STREAM 参考值的 2.1 倍。在该参考值下，并发的冷预填需要组级执行器决定「并发变慢」还是「错峰满速」，即发放「遍令牌」（§5.4）。

命题 3（归并边界，诊断式）　对需要等所有分片的归并点： $$T_{boundary}\approx\max_r T_{ready,r}+T_{comm,exposed}.$$ 只优化非关键 rank，不会提前归并边界。各 rank 的就绪时间并不独立，因为它们共享主存和中转路径。这个式子只用于诊断，不是完整的预测模型。

NCCL 中转　4090 不支持 P2P 时，集合通信经主存中转，会与专家流争用同一份 $B_M$。每个归并点的数据量约为 token 数 × hidden × 字节宽度 × $2(n-1)/n$。超连接是否放大有效 hidden，需要在实现中确认。解码阶段数据量小；长预填阶段可能可观，待测。

4.7 解码理论值：以模型代替经验目标 推导

v5.2 及以前把“持续解码 > 30 tok/s”作为体验线，它是经验设定，没有模型依据。本节用 §4.3 的串行模型和 §4.4 的链路预算，按执行结构给出每路解码的理论值，作为评价实现的基准。

记每 token 未命中搬运时间 $X=m\,S_{tok}/B_P$，一步的固定部分 $F(B,L)=t_0+kL+t_{req}(B-1)$（$kL$ 按 §4.4 的算法只计一次）。每路解码速度为：

$$R_{serial}=\frac{1}{F+B\,X},\qquad R_{overlap}=\frac{1}{\max(F,\ B\,X)},\qquad R_{link}=(1-u)\,\frac{B_P}{B\,m\,S_{tok}}.$$
  • $R_{serial}$ 是当前实现的理论值：整步一张 CUDA Graph，传输与计算串行相加（§4.3 假设 1）。
  • $R_{overlap}$ 是两路以上错相位重叠的理想值（§5.3，M4）。单路内部的数据依赖无法自我重叠，单路不适用。
  • $R_{link}$ 是链路上界，只取决于失误率；任何执行结构都不能超过它（下表取 $u=0$）。

5.1 设计原则

  1. 以字节与遍数计成本，而不是 token 数：准入、切段、插入都按「还要搬几遍、占多少链路与主存时间」来决策。

5.3 两路错相位重叠解码（M4）方案

当前实现中，两路解码在批内同步推进，传输与计算串行相加。若两路错开半步，让 A 的未命中搬运与 B 的计算重叠，就能把 PCIe 时间与 GPU 时间并行起来（图 5）。它不减少搬运字节，只重排 PCIe 时间，属于 PCIe 时间预算的另一种用法，不依赖 CPU 路径或新的数值路径。

5.4 多 GPU 组级执行器 方案

多卡时，每张卡都有自己的 PCIe 链路，但主存读带宽、CPU 和 NCCL 中转路径是组内共享的。组级执行器用组的完成时间和请求时限来评价动作，而不是让每个 rank 各自追求局部带宽。它有五个动作：

  1. G1 遍令牌准入：控制同时进行的整池流数 $k$（命题 2）。$k\,B_P\le B_M$ 时各流满速；超过时每流约为 $B_M/k$。执行器按各请求的首 token 时限，在「并发变慢」与「错峰满速」之间选择；新预填按令牌排队，并与 M2 的按遍合批组合。
  2. G2 关键 rank 优先：依据命题 3，归并边界由最慢 rank 决定。缺失传输与插入的解码步按「是否在关键路径上」排序。
  3. G3 配置选择：依据 G0 显存账在 1×TP4、2×TP2、4×TP1 之间选择（§5.5）。分组在一次启动内固定，不在运行中改变 TP 宽度。
  4. G4 会话亲和：4×TP1 时，会话固定在一张卡上，避免 KV/GDN 状态迁移。
  5. G5 NUMA 就近放置：专家池按 GPU 所在 NUMA 节点分片放置，减少跨 UPI 读取。

执行器必须保留集合通信的顺序与图捕获契约，不能把各卡独立的队列当作可以任意交错。

6 实验方法

6.1 轮次与归因

  • 轮次的定义：一轮 = 代码版本 + 启动命令 + 模型 + 运行状态，跑固定套件后给出判定。基础代码换代时开新一代，只在同一代内比较增量。一轮只改一个变量。
  • 起服务前的检查：断言 freetoken.__file__ 指向预期工作树；通过单写者门（无监听、无显存占用、无其他批次进程）；A/B 对照前逐字段比对两边解析出的参数。
  • 因果对照：采用冷/热 × 开/关四格配对。冷格每格用独立进程重建状态。段数取自执行事件，不由 TTFT 反推。
  • 首枪：单独记录。第一枪偏慢 13–16%，跨轮比较时不计入。
  • 数值门（单卡无损改动）：与父轮 temp0 输出逐位一致，覆盖全文、切块边界和每遍 H2D 字节。

6.2 指标与数据版本

  • 首 token：客户端首 token 包含排队；另记首个业务有用事件。
  • 解码速度：$(n-1)/(t_{last}-t_{first})$。
  • 总吞吐：按共同墙钟窗口内的真实输出计，不把每路均值相加。

9 正确性准入

v5 的正确性分类。（1）冷路径：API单独臂、串行首请求与新进程冷参照 的 8257-token 三次同 SHA，在绑定协议内可复现；（2）同结构热/冷：T17 的 28/28 仅覆盖已测 ≥65 尾段；（3）并发：不保证，即使 temperature=0，前缀缓存命中或并发也可产生不同输出。缺少 checkpoint 写入的 ≤64 分支不等于状态未更新，只表示该分支的正确性仍待证〔FTD-20261009-1〕。

改变执行路径的改动（例如用快照恢复状态代替整段重算）分四层准入。前三层用于定位差异，端到端行为仍须按单独批准的范围验收：

  1. 存储传输等价：保存前副本与恢复后副本逐位相等。
  2. 完整续算状态：GDN、KV、有效长度、位置、卷积 / PLE 窗口等实际存在的状态与元数据，对应同一合法前缀。
  3. 固定后续 token 的数值检查：比较恢复路径与参考路径的 state 和 logits，定位首个差异层。
  4. 端到端行为：生成、工具调用、取消与回收。

容差必须独立标定：不能用被检验路径自己的实测偏差作为容差。历史冷/热重放的测量有效性与机制归因分开记录：跨进程 cold 36/36、warm 36/36 相等；同进程 cold/hot 仅 3/36 相等、33/36 不同，结果限于历史提交，不能推广到当前候选。冷、热与并发证据分别见 §10〔历史冷热重放〕。

指定口令观察的边界。共享前缀判别使用3个新服务、5次请求；五条回复均违反冻结的逐行字符串文法，单独冷请求也出现异常。未观察到对方完整口令、U+FFFD或非法控制字符，因而不把该现象单独归因为并发干扰。GLACIER 热请求命中8256、现算30 token，属于 ≤64 不写检查点分支；其单独冷、串行热及并发热全文同 SHA 只是旁证，不是逐位正确性证明。SUNSTONE 的冷与并发全文不同，也不能宣称所有任务正确。内部分类定义与原判保留于附录 A.4〔双口令并发观察〕〔共享前缀冷热并发判别〕。

TP 数值门（候选，第一阶段不采纳）：

  1. TP-$n$ 同配置两次运行逐位一致。
  2. 相对单卡，首个分歧位置上前两名 token 的 logit 差低于阈值，阈值由单卡「批形状不同」造成的分歧标定。
  3. 60 题质量差距在噪声内。

10 并发与可重复性边界

10.1 冷可复现

冷路径仅在输入、配置、服务隔离与 SHA 绑定的协议中可复现。8257-token 同一提示在三个新进程、两个提交（effb996 / 481d3a7）上得到相同正文，完整 SHA256 为 9845c3860e326f437ad9fa6759c0c7e1bcca71a4ce3a37b702c5a76c9dd1cf4c。这构成绑定协议内的范围证据，不扩展为任意请求保证（对应轮次及各臂见附录 A.4）〔API并发对照〕〔冷热串行对照〕〔新进程冷参照〕。

10.2 热请求可以与普通冷请求不同；同结构参照内一致

热请求可以与普通冷请求不同。冷/热串行对照中，同一8257-token提示的第二次请求命中8256 token，其正文与冷请求从第83字符起不同；历史冷/热重放中也有 33/36 对全文不同。前者来自当前候选的缓存命中观察，后者限于历史提交，两者都不能由 temperature=0 排除〔冷热串行对照〕〔历史冷热重放〕。

T17 的28/28证明的是已测尾段65、4095、4096、4097、8191、8192、8193的同结构 warm 与独立 cold reference 之间，四类状态、token和全文逐位一致；它不证明所有≥65尾段，也不证明与普通冷请求不同 chunk 结构之间相等。≤64（含1 token）仍待证〔同结构续算等价验证〕。

10.3 并发不保证

本文不保证批不变性。API并发对照中，同一请求的并发臂与单独臂正文从第83字符起不同，即使 temperature=0 也未保持全文一致。这里报告的是该指定负载对并发/批上下文的输出敏感性；未证明实际物理 batch 结构或差异的数值成因。指定口令 canary 未观察到对方完整口令，不等于保证批不变性〔API并发对照〕〔双口令并发观察〕。

11 结论与后续工作

v5.1 的结论是受限的：专家流与 PCIe 时间预算的推导仍成立；K1修复后已获得28/28同结构、已测≥65尾段的逐位证据；冷、同结构热/冷、并发三类结论不能互相替代。跨系统扩展评估仍未执行，不据准备方案作性能或质量承诺。

在主存卸载 MoE 上，预填成本的单位是「专家池被搬了几遍」，这一点原文已经观察到。本文把它推到服务层面的后果上，得到以下结论：

  • 首 token 实测：在当前整层加载路径下，短后缀轮次的首 token 由段数而非 token 数决定，实现地板为一遍。开启锚点检查点时，冷请求多付一遍；锚点切段对照 的三组冷配对复现了 cut 2→1，而六次 snapshot 成功计数全为 0，故不能归因为已证明的快照能力〔锚点切段对照〕。
  • PCIe 时间 推导：预填遍与解码未命中共用一份 PCIe 时间，一遍约等于 233 个解码 token。
  • 多卡 推导 / 方案：在每片只取一次的张量并行下，一遍的主存读字节与卡数无关；卡数超过拐点 $n^\star=B_M/B_P$ 后，搬运下界不再下降，收益可能主要来自驻留率。共享主存带宽要求组级执行器按预算发放遍令牌。以上都没有多卡实测。
  • 正确性 实测：T17 在已测同结构尾段 ≥65 上 28/28 逐位一致；≤64 与并发分别仍待证和不保证〔FTD-20261009-1〕。
  • 解码理论值 推导 / 实测：以发布配置实测失误率计，单路 32K 理论值约 36.6 tok/s，两路每路串行约 21.8、上界约 37.8；实测单路（≤ 64K）为所在结构理论值的 94–101%，两路为 103–105%，除一组单路 32K（93.9%）外都达到 95% 判据；87K 为 88%。原“每路 > 30”目标由此替换（§4.7、§8.3）。

M5 收益待证：51段中15段恰为64 token，走T17未覆盖的不写检查点分支。短段计数不能替代正确性或性能证据。后续工作顺序及前置条件为：

  1. 先获得尾段 ≤64（含1 token）的正确性证据，再验证 M5 的性能收益；
  2. M1；
  3. M4（首个原型 b162 只达到重叠理论值的 13.7%，原型阶段结束；机制本身未被检验）；

附录 D　推导细节

D.1 $f(n)$ 的偏差范围

真实比例无条件地落在 $[\,10/512,\ \min(1,10n/512)\,]$ 之内。

  • token 独立同分布时：设每个专家被选中的概率为 $p_i$，$\sum_i p_i=10$。用到的专家数期望为 $\sum_i[1-(1-p_i)^n]$。$g(p)=1-(1-p)^n$ 是凹函数，由 Jensen 不等式，均匀分布时这个和最大。所以在独立同分布下，热专家只会让 $f(n)$ 变小。
  • 其他情形：token 之间分布不同或负相关时，可能超过 $f(n)$。偏差方向并不固定，但有界。

D.2 等待窗口的一阶条件

  • 窗口 $W$ 让首个请求多等 $W$。
  • 窗口内再到达一个请求的概率约为 $\lambda W$，它能省约 $D-W$。
  • 净收益为 $W[\lambda(D-W)-1]$，为正的条件是 $\lambda(D-W)>1$。
  • 若把省下的一遍还给解码（约 233 个 token 的链路时间），评价目标改变，需另算。

D.3 64K 只靠 MoE 提速的算力需求

  • 每 token MoE 约 4.72 GFLOP，65,412 token 约为 309 TFLOP。
  • 非 MoE 取 8.1 s 时，MoE 预算为 1.7–1.9 s（差别在于是否扣除拟合常数 0.2 s），对应 163–182 TFLOPS。
  • 非 MoE 取 9.7 s 时，预算为 0.1–0.3 s，需要峰值的 6–19 倍。
