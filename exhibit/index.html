D1

长预填改层优先

部分过门 代码 预填调度 / 专家搬运

主要门全过，未达 ≤9 s 点估计　验收门：冷 32K 首 token ≤ 9 s（未达）；其余门全过

方法论 → 机制：把预填的两重循环从「块 → 层」改成「层 → 块」：第 l 层的整层专家进双缓冲后，这一层把整条请求的所有子块依次算完，再进第 l+1 层。双缓冲生命周期从「每块一次 begin_prefill」改成「每条请求一次」，release_prefill_layer 推迟到本层最后一个子块之后。整条请求一次准入，模型内部再按 4096 切子块控制层间激活显存。

为什么改这里：基线的 21.52 s 里，搬运被重复了 8 次（每块都重搬整池）。层优先把 8 次搬运算成 1 次。

开关：--prefill-layer-major（默认关；只对「单条、长于一个 chunk、无多模态」的预填生效，短提示/解码/多请求排队路径零改动）

D3

线性注意力多锚检查点

部分过门 代码 前缀缓存 / GDN 状态

部分过门：整段重发 2.69 s 过，中途编辑 8.14 s 不过　验收门：编辑后轮次首 token ≤ 4 s（一半场景过）

方法论 → 机制：第一步两步：(1) 锚点集合匹配——除工具调用起始 token 外，把 <think> 结束、<|im_end|> 也纳入锚集合，解码命中改集合判定；(2) 预填锚封顶——_add_one_req 扫描 prompt token ids，命中锚集合时把 chunk_size 截到该锚的页对齐边界，使块末的 GDN 状态恰好编码 [0, cut) 个 token。目标是让 Agent 删思考块/截断工具输出后能从最近存活锚恢复。

为什么改这里：Agent 多轮里前缀会分叉，纯前缀缓存只能整段重发命中；锚点让分叉后的轮次能只重算后缀。

开关：锚集合随 --enable-special-token-ckpt 生效（默认关）；诊断开关 FT_D3_ANCHOR_MODE / FT_D3_TREE_DUMP / FT_D3_TRACE 均默认关

根因定位

位置：scheduler/scheduler.py:_process_last_data

if isinstance(req, ChunkedReq):
    # Don't cache intermediate chunks; the full prompt is cached once when the
    # final chunk is processed. Caching here snapshots a handle the next chunk
    # already copied (overlap), so cache_req double-frees the prior chunk.

引擎显式跳过中间预填块的缓存提交。_cache_req_hybrid 的非 finish 分支（注释写着 Prefill chunk commit: donate the frozen snapshot）在分块预填下从不执行，只在预填→解码过渡那一步跑一次、捐一次。空闲时树导出显示整棵树只有结束捐赠的 13120 一个节点；捐赠跟踪打印的 cached_len=13182 ext=1 也来自解码步。

阻塞：锚块中间提交、每请求多快照槽、恢复选择——后两项都被这一项阻塞。

剩余差距 / 后续：剩余核心工程项是让锚块能做中间提交且不触发 double-free，三条候选路径（关 overlap / 页所有权共享 / 延后 overlap 时序）及代价见 RESULTS_DEV_D3_20261003.md §5。

二、已否决的方案

实测为负或触发硬门，同样列出以免重复试。

方案层实测否决理由
NUMA 重绑（专家池按节点分片）配置冷 32K 解码 36.11 tok/s < 基线 37.52（也低于 D2 点估计 42）收益为负。方案规定：若实测显示该杠杆无效则停做——按此停 D2。

D3 锚封顶切到第一个锚（FT_D3_ANCHOR_MODE=first）代码冷启动 23.0 s（vs last 7.93 s，慢 2.9 倍），中途编辑轮仍零命中 21.4 s切碎只增加搬运轮数，不解决根因（预填无快照）。
