## 需要更正的旧表述

1. **ollama 的影响范围。** 容器的 CpusetCpus 是 "0,2"，24 个线程只争用逻辑 CPU 0 和 2，不是全机。
   - R048b 的 V0（cores 0..22，与这两个 CPU 重叠）跌到 1.97 tok/s，A/V0 为 14.4 倍，佐证了"自旋屏障 + 落后线程"的机制。
   - A、B、S 三臂都避开了 0 和 2，所以 D08 单路负结果（最好 31.9，参照 36.6）基本不受 ollama 影响。主会话 20:45 的"hybrid 无收益可能是 ollama 导致"只对 V0 和 E1-R002 成立。
   - b162 主线程没有绑核，受 ollama 的影响也应该很小，此前"可能有影响"的说法降级。
2. **主会话的两路 CPU 模拟（two_lane_share_sim.py）。** 独审发现四处语义和计数问题，所以那六个数字不能当作已验证的每路 m。方向得到了 GPU 实测支持（模拟 40–43%，实测 38.2%），实测数据取代模拟数据。
3. **论文 v5.3 中需要修订的地方。**
   - 两路理论值：串行 21.5/21.8 改为 16.6；重叠 37.8 改为 23.9（内容不同）；删除"m ≤ 30.4% 已满足"。
   - R045 的 103–105% 要说明是近似重复提示，应改用 Y 组的 m（27.7%）。
   - b162 的判词。
   - 128K：解码只降 4.2%，与模型的 4.0% 一致，但 129,024 token 冷请求 OOM，暂不作为发布配置。
   - D08 的适用范围。

## 总体含义（已有模型闭环支持）

单卡、2700 槽、两路内容不同时：
- 串行每路约 16.6 tok/s（实测 17.0）；
- 理想错相位每路 23.9 tok/s；
- "两路每路 30"在现有机制组合下都达不到。

能改变链路约束的方向只剩三类：容量、每次失误的字节数、让失误不经过链路（hybrid，只测过单路）。
