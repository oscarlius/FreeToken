## 更正第 0 节"已知事实"

1. **"同窗口"说法有误。** hybrid 对 offload 的 +12% / +49%，是 retry2 与历史 offload 参照的跨窗口比较。真正的同窗口 A/B 是今天的 window02：

   | | hybrid | offload | 提升 |
   |---|---|---|---|
   | 单路 | 35.55 / 36.59 | 29.62–30.19 | +21% |
   | 两路每路 | 25.96–26.27 | 16.81–16.98 | +55% |

   另外，hybrid 在同一服务内重复同一请求，输出也不逐位一致（J4 affected）。

2. **"每专家 0.20–0.24 对 0.071 ms、差约 3 倍"作废。** 算法研究（`plan/HYBRID_ALGORITHM_RESEARCH_20261011.md`）改为下面的一步耗时模型：

   t_step ≈ S_GPU + Σ_层 max(G + f·t_P, O_C + (n − f)·t_C)

   各项含义：

   | 记号 | 含义 |
   |---|---|
   | S_GPU | 每步 GPU 串行部分 |
   | G | 本层 GPU 自身的计算 |
   | n | 本层未命中的专家数 |
   | f | 其中经 PCIe 取到 GPU 的专家数 |
   | t_P | 每个专家的 PCIe 取数时间 |
   | t_C | 每个专家的 CPU 计算时间 |
   | O_C | 每层 CPU 路径的固定开销 |

   CPU 只能和同层 GPU 的 MoE 计算并行。按 retry2 标定（推算）：

   | 项 | FreeToken | Strata |
   |---|---|---|
   | 每层 CPU 路径固定开销 O_C | 约 0.19–0.26 ms（每步 9–12.5 ms） | — |
   | 每专家边际代价 t_C | 约 0.04–0.07 ms | 约 0.036–0.071 ms（拟合不稳） |

   **差距主因是每层固定开销和 GPU 串行部分，不是每专家带宽。**

3. **Strata S1 是可复现配置。** `--pcie-frac 0` 加上关闭自适应，按 Strata 文档会降低解码速度。Strata 的默认配置会把一部分未命中专家经 PCIe 取到 GPU。

## 调整调研重点

- **Q4（线程模型）升为首要问题。** 已知 FreeToken 的 `cpu_moe_ext.cpp` 约 1870–1968 行用条件变量唤醒工作线程，再用条件变量等待完成。请写清楚以下几点，并与 Strata 的 `pool.cpp` 逐项对照：
  - 每层要经过几次睡眠/唤醒、几次屏障；
  - 协调线程是否也会睡眠；
  - 唤醒到开始计算之间有哪些步骤。
- **Q6、Q7 的重点放在每层的固定成本上**，包括：
  - 每层的 D2H / H2D 拷贝；
  - stream / event 同步；
  - 是否打断了 CUDA Graph。
- **第 4 节微基准改为测两项**（时间限制不变）：
  1. **空任务派发延迟**：派一个不做计算的任务给线程池，再等待它完成，测这一来一回的耗时，即 O_C 的下限。线程数 1 / 12 / 24 各测一组。
  2. **每专家边际代价**：分别测 1、3、10 个专家的批，用斜率得出 t_C。

  有现成入口就两边都测；FreeToken 一边可以通过 Python 扩展调用。没有现成入口，就只做读码分析。
- **PORTABLE_IDEAS.md 的第一项必须评估"自旋线程池"。** 要写清楚：自旋时 CPU 占用会上升，对生产服务和其他进程有什么影响；还要说明如何在空闲时退回睡眠。
