## 目标

把「预填按锚点切段」（我方 D3 的预填锚封顶，提交 e92fdf5 / cd450be）从 `--enable-special-token-ckpt` 中拆出来，变成独立可关的开关；**解码期快照与锚点匹配保持不变**。同时让每个预填段带上「为什么在这里切」的记录。

## 范围

1. 新开关：`ServerArgs.prefill_anchor_cut: bool = True`，命令行 `--no-prefill-anchor-cut`（`store_false`）。默认值保持当前行为（开关开 + ckpt 开时照旧切段），所以默认路径逐位不变。
2. 开关为 False 时：预填准入**不再因锚点切段**；`toolcall_anchor_id`、解码期快照（`snapshot_toolcall_anchor`）、锚点集合匹配全部照旧。
3. 逐段切段原因：每个预填段记录 `seg_reason`（枚举，至少：`anchor_cap`、`token_budget`、`layer_major_whole`、`continuation`、`other`），以及该段内各请求的 `rid` 与 `new_tokens`、`cached_tokens`。写入两处：
   - D0 记录 `d0_prefill.jsonl` 每行新增字段 `seg_reason`、`reqs: [{rid, new_tokens, cached_tokens}]`（仅 `FT_DEV_D0=1` 时）；
   - `serve.log` 新增一行（仅 `FT_DEV_D0=1` 时）：`D0 seg: idx=<k> reason=<…> reqs=<rid:new/cached,…>`，便于 01 用 grep 对齐。
4. 快照计数：解码期快照每成功一次累加计数，在 `FT_DEV_D0=1` 时随 `d0_decode.json` 输出 `anchor_snapshots_taken`，并在服务退出前打印一行 `D0 anchor_snapshots_taken=<n>`。

## 非目标

- 不做多锚快照（机制 D12 第二步 → D09）。
- 不改 `FT_D3_ANCHOR_MODE` 的语义（`prefill.py:179`，默认 last）。
- 不修 `scheduler.py:398` 解码热路径无条件读 `d3_extra_anchor_ids` 的已知缺陷（会影响 2 例已知失败测试的归因；单独处理时另开卡）。如果顺手修，必须单独提交并在交付记录中说明测试数变化。

## 设计约束

- 默认（不加 `--no-prefill-anchor-cut`、不设 `FT_DEV_D0`）：与 c721c74 **逐位一致**（全文、切块边界、每遍 H2D）。
- `FT_DEV_D0=1` 时新增字段只追加，不改已有字段名与含义（T02 的对齐脚本依赖 `chunk/wall_s/h2d_*/d2d_*/layers`）。
- `rid` 用调度器里请求的稳定编号（与 `serve.log` 其他行一致），跨段不变。
- `seg_reason` 的枚举值与 D02 共享，写进一个模块常量，D02 直接复用。
- 新属性在类上声明默认值；热路径不得无条件读未初始化属性。

- 低。主要风险是快照覆盖面：D3 的切段原本可能让某些锚点状态在预填期就被保存，关掉后这部分状态只能靠解码期快照；G4 用来发现这一点。若 G4 不过，交付记录写明「切段关闭导致快照覆盖减少」，T03 会按「快照退化」行给出 `not_met`。
