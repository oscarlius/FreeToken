## 要解决的行为

当一次 **offload GPU prefill 的 MoE forward 预填段** token 数满足 `0 < n <=` 显式阈值时，在每个 MoE 层的路由结果可用后，仅把该层 `topk_ids` 实际涉及的唯一专家搬进可用槽位，再按槽位视图计算；零、超过阈值或不满足前提时保留现有整层路径。默认阈值为 `0`，即功能关闭并逐字节保持现有路径。2026-10-08 17:16澄清：n对应实际`hidden_states.shape[0]`，一条请求的未缓存后缀可能经anchor切成多段，不能拿整条请求后缀分布当代码覆盖率。

该选择只按本次 prefill 的实际 token 数和明确配置决定；不从 D15 画像、历史命中、请求内容或性能读数动态推断。阈值的候选值必须先由 `E2-R046g` 的已封存 route summary 分桶得出，随后才可进入 GPU A/B；本卡不预设 `1024` 或任何 Strata 数值。

## 实施范围

1. 在 `python/freetoken/engine/config.py`、`server/args.py` 和实际配置传递链增加一个可见的整数 ServerArgs（建议名 `moe_prefill_routed_only_max_tokens`，默认 `0`）。启动日志和 `serve_args` 必须可见它；负值或非法类型必须拒绝；请求实际token数在运行时与阈值比较，阈值大于某次请求token数并非非法配置。
2. 在 `python/freetoken/layers/moe.py` 的 `_prefill_routed` 建立唯一分流点。只在 `0 < n <= configured_threshold`、GPU offload、可服务的 pinned 层和不与预填双缓冲并发的条件同时满足时进入 routed-only 分支；否则保留现有 `prefill_overlap` 或 `materialize_layer` 原样行为。
3. 在 `python/freetoken/moe/offload_cache.py` 增加受限的 prefill routed-only prepare/release 对：
   - 在 `topk_ids` 被改写前去重原始专家号；
   - 通过现有 `ensure_experts` / `copy_missing` 和 slot 映射装入缺失专家；

   - 以事件或现有同步边界确保不覆盖仍被 decode GEMM 使用的槽位；静态资格不满足（overlap、unpinned/pageable、hybrid/CPU MoE）走整层路径并记录 fallback。`ensure_experts` 已改写 ids 后的 copy/映射异常必须 fail closed 并报错，不能拿已改写 ids 走旧路径。
