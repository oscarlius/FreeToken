## 动机

- 当前每 token 搬运未命中专家约 292 MB（m = 21.93%，专家槽 12.8%）。两路每路 30 tok/s，按串行模型需要把 m 降到约 12.5%，或者补带宽。
- FreeToken 的缓存是全局 LRU。Strata 用「离线路由画像排名 + 在线自适应置换」：社区数据中，重复会话后命中率从 70–84% 升到 91–92%（不同量化、不同显卡，**不能外推到本机，只说明值得测**）。

## 本卡要做的

1. **画像工具**：读卡D07 的路由轨迹（T06 的产物），生成 (层, 专家) 访问排名，输出 STRP 兼容格式。
2. **策略开关** `FT_DEV_EXPERT_POLICY`，取值 `lru`（默认，即现状）、`profile`、`profile+adapt`：
   - `profile`：启动时按画像预置热门专家，其余槽仍按 LRU 管理。
   - `profile+adapt`：每 N 步按近期计数做有限次置换（N 与每次置换数作为参数）。
   - 置换必须走现有搬运与槽位管理：`moe/offload_cache.py`；调用点 `moe/offload_kernels.py:28`，实现在 `flashlib.kernels.slot_cache`（`lru_ensure`）。该包不在仓库内，位于服务器 venv，用 `/data2/FreeToken/venv/bin/python -c "import flashlib.kernels.slot_cache as m; print(m.__file__)"` 定位。
   - **槽位区域**：预填双缓冲借用前 2E 个槽（E = 每层专家数 `num_experts`），并把它们的 `usage` 置 0、成为 `argmin` 的首选牺牲者（E2-base 的 `offload_cache.py:890-893`、`918-923`），每次预填都会覆盖。画像预置与置换只能放在**槽号 ≥ 2E** 的区域，否则收益会在每次预填后被清空。
   - **在用保护**：现有缓存**没有引用计数**。置换只在两个解码步之间、拷贝流同步之后执行，并且不得与预填并发；如需要更细的保护，自建引用计数并加测试。
3. **计数器**：每步的命中、未命中、置换搬运字节，写入 D0 记录（只在 D0 开启时）。

## 适用范围

**只适用于 offload 路径**（`--moe-strategy offload`）。读码核实：解码时每个路由一个程序、完整 K 归约，按 top-k 位置求和（`moe/fused_nvfp4.py` 的 `_decode_gemm`、`moe_sum_reduce_triton`）；槽号只用于取权重，命中与未命中走同一个内核；预填命中走 D2D，字节相同。因此在 offload 路径上，「策略不改数值」可以作为门。hybrid / cpu 路径的 CPU 与 GPU 内核不同，不适用，与卡D08 隔离。

## 风险

- 置换会占用 PCIe，在预填整池流期间可能和预填争带宽。置换只在解码步之间、且没有预填进行时执行。
- 画像对负载敏感：用 `seed12k` 生成画像并调参，在 `seed_45k`、`seed_real` 和两路负载上做留出验证，不能在同一条轨迹上调参再报告收益。
