## 实现与口径

1. `Engine.forward_batch()` 在真实预填批次开始冻结元数据，在本批 GPU 计算完成处同步 `end_prefill()` 写出；下一段、空闲回调、退出钩子均不承担末段落盘。warmup 直接调用模型，不生成真实预填记录。段原因和 `reqs` 沿用 D01，`t_start/t_end` 为 `time.time()`。
2. 每个真实解码步追加 `d0_decode_steps.jsonl`。按现有累计计数器的步前/步后差值取得逐层缺失数；GPU 模式全部缺失行取回，hybrid 模式使用 capped fetch。`h2d_bytes` 等于实际取回专家行数乘完整专家权重 bank 行字节数，hybrid 的 `cpu_experts` 为缺失减取回。请求编号采用实际 `Req.uid`。
3. 普通 D0 保留原 CUDA Graph；图捕获和 warmup 不调用逐步 recorder 的 begin/end。图 padding 的 dummy 执行计入实际拷贝/缺失量；`bs/rids` 是真实请求，另有 `padded_bs` 时标出执行 padding。
4. 时间线仅在双开关下启用，日志打印 `D0 TIMELINE: cuda graph disabled`。每个 CUDA event 的时间为相对该步 GPU 起点的毫秒，前 N 步记录到 `d0_decode_timeline.jsonl`；墙钟 `t` 供客户端对齐。GPU 计算事件标 `compute_scope=gpu_experts`；CPU 层是 `cpu_stream_wait_and_result` 包络，CPU stream 的 submit/wait/result copy 保持原路径。
5. 离线工具按线性插值算中位数和 P90。重叠比例是拷贝区间并集与计算区间并集的交集除该步时长；气泡是这些事件的未覆盖时长，包含 attention/routing/CPU 等待等，**不代表 GPU 空闲**。
6. 原两秒聚合 `d0_decode.json` 保留，追加 `sm_clock_mhz`；按 CUDA 设备 UUID 查询 `nvidia-smi`，失败为 null。每行 JSONL 追加、行缓冲、flush 后关闭，写入异常上抛，已写完整行保留。
