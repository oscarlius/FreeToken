**更正后的四条主结论：**

1. **OOM 是生产可用性风险。**
   - 生产配置下，95K 冷请求在新起服务上也会 OOM；87K 的结果取决于历史状态：window02 的 O1、O2 都 OOM，本窗口 S1 通过。
   - 每次 OOM 都会触发整模型重载，用时 235 秒；在此期间服务对所有用户不可用。
2. **window02 的 J4（"hybrid 同一服务内重复请求输出不一致"）是误判。**
   - J4 比较的是 X 的第 1 次与第 2 次请求，也就是冷请求对命中缓存的热请求（热请求命中 1,152 / 1,179 token，现算尾段 27 token）。
   - **offload 在同样的比较中也从第 454 字符分叉**：window02 的 O1、O2 和本窗口 S1，三个独立服务结果相同。所以这不是 hybrid 特有的问题。
   - hybrid 真正特有的、依赖缓存状态的证据另有一条：window02 中未预热的 H2 与预热过的 H1，冷请求从第 600 字符起不同；而 offload 的计算与缓存状态无关（按构造如此）。所以"默认 hybrid 依赖缓存状态"这一判断仍然成立，用户把它定为可选模式的依据没有被推翻。
3. **按预登记判据，可复现 hybrid 判"不可复现"。但事后对照显示，这套判据不区分 hybrid 与 offload。**
   - 判据中不成立的两项（两路两次运行相同；S5 单路对 S4 单路相同），offload 在同一窗口里也不成立：两路第 1 路在第 806 字符分叉；冷对热在第 454 字符分叉。
   - 改用"与 offload 同类比较"后（事后），HR-a、HR-b 在已测的每一项上都与 offload 一样可复现：热对热相同；HR-b 跨服务冷对冷也相同。
   - 代码注释写明，max-fetch 0 时 GPU 缓存始终是冷的、所有未命中都在 CPU 上算，所以按构造它与缓存状态无关。但本窗口没有直接测"不同历史下的冷请求"。
   - 要正式结论，须另做一次预登记的确认测试（§6）。
4. **反常现象：在 max-fetch 0 下，fp32 的 CPU 路径比 W4A8 快约 1.6 倍。**
   - 数据：单路 28.61 对 18.05，两路每路 18.91 对 11.20。
   - 如果复测证实，默认 hybrid 改用 fp32 可能同时变快、并去掉激活量化。顺序混杂未排除，须复测。

**说明：** offload 冷对热的 454 分叉，属于论文 §10.2 已写明的限制"热请求可以与普通冷请求不同"（原例：8,257 token 的提示从第 83 字符分叉）。它不是 T17 的反例：T17 比较的是热请求与同结构的冷参照，不是与普通冷请求比较。所以 window02 的 J4 本应在设计阶段就被识别为"已知的共性"。

**判定：**

- **按 §6.2 预登记字面：** HR-a、HR-b 都"不可复现"（两路一项不成立；S5 对 S4 单路 1 不成立）。
- **这两项对 offload 同样不成立。** 所以判据不区分 hybrid 与 offload，是主会话的设计错误（§5）。

- **默认 hybrid 依赖缓存状态的唯一直接证据是 H2 对 H1 的 600。** 这一条仍然成立。
- **顺带：** 默认 hybrid 的热请求输出（window02 H1 第 2 次）与 offload 热请求逐字相同（SHA `2e211eee8728`）。数值差异只在接近并列的 token 处才会改变输出，所以文本相同不代表 logit 相同。

**与论文的关系：**

- offload 冷对热的 454 分叉，与论文 §10.2"热请求可以与普通冷请求不同"一致，是那条已知限制的又一例：X 有 1,179 token，热请求命中 1,152，三个服务复现。
- 它不构成 T17 的反例，因为 T17 比较的是热请求与同结构冷参照。
- v5.8 可以在 §10.2 补上这一例，并在 §7.7 撤回 J4 的 hybrid 特有归因。

## 5. 主会话的错误（自省）

1. **window02 的 J4 误判（影响最大）。**
   - 主会话写的 window02 指令，把"重复 1 对 重复 2"当作自身复现性检查，没有意识到第 1 次是冷请求、第 2 次是热请求，也没有设 offload 对照。
   - 论文 §10.2 早已写明"热请求可以与普通冷请求不同"，主会话没有把这条已知限制与 J4 对上。
   - 复核 KIMI 时，主会话照单接受了"hybrid 同服务重复不一致"，并写进了论文 v5.6/v5.7、进度页和记忆。
   - 用户把 hybrid 定为可选模式的依据（W4A8、依赖缓存状态）仍然成立，因为有 H2 对 H1 的 600 作为证据；但"同服务重复不一致"这条证据要撤回。
2. **本次可复现判据没有设 offload 对照臂。** 论文 §10.3 已经写明"不保证批不变性"，主会话仍然把"两路 1 = 2"列为判据。
3. **S5 对 S4 的比较混入了冷热差异。** 应比较 S5 单路与 S4 的预热第 1 次（两者都是冷请求）。
4. **D0 公式没考虑批大小。**
5. **A/B 只排了一种顺序。**

**教训（写入指令自检清单）：**
- 凡是"相等/可复现"判据：
  - 先确认基线自己能满足，并在同一窗口设基线对照臂；
  - 比较双方的前缀缓存状态必须相同，都是冷请求或都是热请求。
- 每步统计的分母要带 bs。
- 会影响决策的 A/B 用 ABBA 顺序。
