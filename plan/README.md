### 3.1 任务卡生命周期

```
01 卡：待办 ──(依赖就绪)──► 进行中 ──► 完成（结果文件 + 工件已关闭 + 已上报）
                    │              └──► 异常停止（按 01 README §6，上报）
                    └──(依赖未就绪)──► 阻塞
02 卡：待办 ──► 进行中 ──► 已交付，待 01 验证 ──(T16 + 对应业务卡通过)──► 完成
                                        └──(门不过)──► 退回
后置卡：后置 ──(立项条件满足 + 总负责人批准)──► 待办
```

### 3.2 一轮测量从开始到进入论文

1. 总负责人在卡中分配轮次 ID → 2. 01 执行者按卡生成批次脚本、过门、跑 → 3. 取数、写 `round.json`（`verdict=pending_review`，附 `proposed_verdict`）、关闭目录、写本地结果、上报 → 4. 总负责人追加 `verdict_history` → 5. 总负责人发布新数据版本 `FTD-…` → 6. 论文按 `〔轮次ID｜FTD-…〕` 引用，按规则 §5.2 升版本号。

### 3.3 开发交付到验收

02 交付（填交付记录）→ 01 跑 T16 默认路径逐位门 → 01 跑该卡对应的业务测试卡 → 总负责人标「完成」。
