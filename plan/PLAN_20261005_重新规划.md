## 4. 关键判据的修订

### 4.1 T17：命中续算等价门（替代原「与全冷逐位相等」）

原判据要求「命中续算 = 全冷计算」逐位相等。但两条路径的**分段结构、子块网格和预填模式**都不同。以 R023 为例：冷路径是 512 token 的锚点段加 7745 token 的外段（内部为 4096 + 3649 两个子块，层优先）；命中路径是恢复 8192 后，做 65 token 的**普通**预填。按 GDN 分块扫描与 GEMM 行数的数学，这本来就不是同一个计算顺序。R023、R027 的分叉不能直接判为缺陷，也不能直接放行。

新判据分三层：

1. **状态交接逐位**（硬门）：恢复的四类状态（GDN conv、GDN recurrent、PLE conv、PLE ngram）与源状态逐位相等；首子块 `has_initial_state=True`、坐标为绝对坐标、`fresh_state_indices` 为空。
2. **同结构冷参照**（硬门，有裁定通道）：
   - **参照臂的定义**：一次全冷计算，其**分段边界、每段的子块网格、每段的预填模式（层优先或普通）**与「供体请求 + 续算请求」两次实际执行完全相同。边界清单由工具从命中路径两次请求的 D0 段记录（卡D02 的段原因字段，加卡D14 新增的 `start`、`end`、`mode`、`subchunks`）自动生成，经卡D14 的开发参数 `FT_DEV_PREFILL_SCHEDULE` 注入，不得手写。
   - **前提**：参照臂跨进程重复两次，必须逐位相同。不同即工装或环境问题，停止。
   - **判定**：续算输出（全文与 token ID）预期与参照臂逐位相等。相等则本层通过。不等时，01 一律报 `not_met`，并附按层、按算子的首个差异定位。
   - **裁定**：只有总负责人可以把 `not_met` 改判放行，理由与证据写入 `verdict_history`。只在以下条件同时满足时才考虑：首个差异只出现在受批形状（行数）影响的算子上，且状态交接与坐标全部正确。
3. **合法重排包络**（只记录）：普通全冷对参照臂的状态与 logits 差异，按论文 §9 记录，作为裁定的参考材料。注意：T04 的容差标定尚未闭合（R014、R015），所以包络**不能单独作为放行依据**。

### 4.2 质量

- **规范判卷器**：`evaluator.py（sha256:39f10fa8…）`。题库为 `sha256:bde77ab02bb11539f6ee69861dc441ea3670ed6796d4d27226af1f89f74f9cad`。
- 质量分数只用规范判卷器 `evaluator.py`（sha256:39f10fa8…）判分。产生历史 38/60 的**旧版**内联判分停用，只作历史记录；现版 `benchmark_client.py` 内联调用经 SHA 校验的规范判卷器，结果可直接采用（`00_规则` §6.16、§10.4）。离线重判只用于历史回答。
- 历史结论更正：E0、E2-R004、E2-R009 三批回答用规范判卷器都是 47/60，逐题相同。**没有质量回归**。

### 4.3 D0

- 带 D0 的解码数字只作诊断。差异来源已对账，原因未定（T07 −3.5%，R022 −10%，工作负载、样本和时钟都不同）。
- 性能数只取不开 D0 的生产口径轮次。

### 4.4 等价门的覆盖面（新增规则，写入 `00_规则` 第 10 节）

凡是改变预填、缓存或状态路径的改动，等价门必须同时覆盖以下路径：

- 冷请求。
- 短后缀命中续算。
- 剩余超过 4096 token 的命中续算。
- 多会话批内各槽对单独运行（Strata 的 batch_test 思路）。
