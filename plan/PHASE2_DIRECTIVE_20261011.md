## B. hybrid 验证（GPU，默认 09:30 开始，在观察窗口结束后）

预算 ≤90 分钟，属于压力测试：hybrid 运行时约 21 个 CPU 核满载，累计约 10 分钟。

所有测量的公共设置：
- hybrid 的启动参数沿用重试 2（481d3a7、`--moe-strategy hybrid`、S 臂 numactl/taskset，就绪时限 600 秒）；
- 每个新服务先发 2 个不计成绩的预热请求；
- temperature 设为 0；
- 速度统一用 AIPerf ITL，在服务器本机测（S 类）。

1. **自身复现性。** 在 hybrid 服务中做三组比较：
   - X 单路连续发 2 次，比较两次的输出；
   - 新起一个 hybrid 服务，第一个请求用 X 单路，与上一服务的输出比较（冷对热）；
   - X 两路连续跑 2 次，比较两次的输出。

   **预登记读法：** 三组都逐字相同，记为"hybrid 在给定批组成下可以复现"；任何一组不同，记为"输出受缓存或时序影响"，回报用户，由用户裁定 hybrid 只作为可选模式还是进入发布路径。
2. **质量等价。** 对 offload（481）和 hybrid 两种服务，各用 quality60 标准评分器（`evaluation/quality60`，SDK + pytest）跑一遍，两臂用同一个客户端。

   **判据：** hybrid 得分 ≥ offload 得分 − 3（共 60 题）。低于这个分数就不进入组合测试，先回报。
3. **同一窗口内的速度 A/B。** 按 offload → hybrid → offload 的顺序起三个服务，每个服务内每种负载各测 2 次：
   - X 单路、X 两路（输入 1.2K，256 token）；
   - 32K 单路：使用 b163 / S1 冻结的 32,064 token 输入，生成 128 token；
   - 32K 两路：使用 R048b 冻结的 `dec32k_s3A` / `s3B` 两条负载，取原始载荷，SHA 记入回执。

   **预登记：**
   - 两路：hybrid 每路 ≥ 两个 offload 服务均值 ×1.15，在 1.2K 和 32K 下都成立 → 两路收益成立。
   - 单路：只记录比值，不作判据。R048b 在 32K 下的跨配置比值是 0.87，今晚 1.2K 下是 1.12；长上下文单路的方向未知。
   - 前后两个 offload 服务的均值相差超过 5% 时，标"漂移"，不下结论。
   - 任一项低于 7.8，判为异常。
