# D11（论文 M3，遍内插解码）立项推演与决定（主会话，2026-10-11T12:10:19+08:00）

**决定：现在不做。** D11 的主要价值在于减少"其他会话停顿"，而这项指标不在体验线中。按推算，它的吞吐收益上限只有 +1.6% 到 +5.6%；作为对照，hybrid 已实测 +49%。

## 参数

参数来自已闭合的串行模型 t = 13.1 + 0.032·L + m·54.77 ms。该模型在真实内容上的实测值为理论值的 97.6–104%。

- **B 一遍预填的时长 T_p**
  - 热轮次约 2.8 s，受搬运限制；
  - 冷 87K 约 18 s，受计算限制，期间 PCIe 约八成时间空闲。
- **A 一步解码 t_d = F + X**
  - F ≈ 13.1 ms，为 GPU 计算；
  - X = m × 54.77 ≈ 21 ms，为 PCIe 搬运，取 m ≈ 38%（R046g G_seed_real 的 D0 实测值为 38.59%）。

## 推演

**插入 k 步后**

- A 的最长停顿：G = T_p' / (k + 1)
- B 的预填被拉长为：T_p' = T_p + k·c
- 边际代价 c 取被占满的那份资源：
  - 热遍：c ≈ X ≈ 21 ms；
  - 冷遍：c ≈ F ≈ 13 ms。

**停顿目标与 B 的代价**

| 场景 | 停顿目标 | 需插入步数 k | 拉长后的预填 T_p' | B 首 token 变慢 |
|---|---|---|---|---|
| 热遍 | G ≤ 0.5 s | 5 | 2.91 s | +3.8% |
| 热遍 | G ≤ 0.2 s | 15 | 3.12 s | +11% |
| 冷遍 | G ≤ 0.5 s | 36 | 18.47 s | +2.6% |

**吞吐上限**

- 每插入一个 token 省下的时间 = 原成本 − c。原成本两路时为 29.4 ms，单路时为 33.9 ms。
- 限定 B 的首 token 最多慢 10%：
  - 每个热遍最多省 0.17 s；
  - 每个冷遍最多省 2.85 s。
- 真实轨迹（1 个冷遍 + 7 个热遍，每个 agent 约 72 s）：上限 ≈ 5.6%。
- 以热轮次为主的长会话：上限 ≈ 1.6–2.4%。
- 以上未计入切换开销、缓存分区带来的失误率上升，以及 CUDA Graph 只能整步插入的限制。
