# 本地收尾计划（2026-10-14）

用户指令：停止新增贡献；合并本地分支，删除应清理的内容，保持最终产品状态。

## 保留边界

- 当前生产 E3 的提交、参数、进程、运维恢复包保持原状；Ollama 保持停止。
- 以线上实际核对的 E3 精确提交作为本地 `product/` 的 `release/e3`，不把 CPU-only 或负结果实验启用到产品。
- 已发布 #686、#688 的源码合并到上游源码仓库的本地收尾分支，CPU 验证后保留；它不是生产部署，不生成新 PR、不推送、不改 GitHub 分支或 PR。
- 论文、原始实验数据、冻结清单、封存判定、运维/回滚包不删除。

## 执行顺序

1. 记录研究、历史引擎、上游引擎和英文论文仓库的 HEAD、refs、工作树及未提交内容；只读核对线上 E3。
2. 所有将删除的分支先建立归档标签，并生成完整 Git bundle；独立验证 bundle。所有将移除工作树的修改、未跟踪文件和有价值的忽略文件先压缩归档并逐项校验。仅可再生缓存允许直接删除。
3. 同一历史链中的论文分支快进合并；两个已交付上游贡献合并并运行合适的 CPU 回归。历史实验只归档，不把未验收功能合入 E3。
4. 独审清理清单；确认备份齐全后移除旧 linked worktrees，再删除已归档的本地实验分支。每个操作检查绝对路径均在本项目范围内，禁止宽泛 clean/prune 或跨框架删除。
5. 将历史引擎主工作树整理为 `product/`，切到 E3；研究仓库移除旧工作树 gitlink，记录归档和恢复方式，更新 README 与协调日志。
6. 核对各仓库分支/工作树、Git 完整性、产品树与 E3 提交一致，以及线上服务身份/健康未改变；提交本地收尾记录。

## 验证与停止条件

- 备份失败、哈希变化、路径越界或无法归属的文件：不删除对应对象，报告保留原因。
- 合并冲突或 CPU 回归失败：修复或保留未部署的集成分支，不改变 E3。
- 不新增 GPU 测量、不停服、不做生成调用。健康检查仅查询 `/health`。
- 未提交的已有研究记录先保存，不能用 reset/checkout 覆盖。
- 最终报告写明实际保留的产品提交、合并提交、删除数量、归档位置和验证范围。
