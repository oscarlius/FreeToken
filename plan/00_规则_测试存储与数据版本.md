## 1. 原始工件（服务器，唯一真相）

### 1.1 位置

```
/data2/_shared/runs/ft_rounds/<轮次ID>/
```

### 1.2 每轮必备文件

| 文件 | 内容 | 谁产生 |
|---|---|---|
| `round.json` | 轮次记录（字段见 §3） | 执行者，收尾时写 |
| `SERVE_CMD.txt` | 实际执行的完整启动命令，**含环境变量与 numactl/taskset 前缀**，逐字 | 批次脚本 `start()` 自动写 |
| `serve.log` | 服务端完整日志 | 批次脚本 |
| `serve_args.txt` | `serve.log` 里的 `Parsed arguments:` 行及其下一行 `ServerArgs(...)` | 批次脚本，就绪后自动抽取 |
| 客户端 JSON | 探针/回放/基准的原始输出（`*.json`、`*.jsonl`、`*.log`） | 批次脚本 |
| D0 记录 | `d0_prefill.jsonl`、`d0_decode.json`（仅当开 `FT_DEV_D0=1`） | 服务端，路径由 `FT_DEV_D0_PATH` 指到本轮目录 |
| `ENV.txt` | 环境快照：时间、commit、`freetoken.__file__`、torch/CUDA、`nvidia-smi`、`numactl -H` 空闲、负载前 8 进程 | 批次脚本 `snap()` |
| `batch.sh` | 本轮实际执行的批次脚本副本 | 批次脚本启动时 `cp "$0"` |
| `MANIFEST.sha256` | 目录内所有文件（除自身与 `round.json`、`round_history/`）的 sha256 | 收尾时生成（§1.4） |
| `round_history/` | `round.json` 的每一版只读副本 `round.v001.json`…，与 `SHA256SUMS` | 收尾时与每次追加时生成 |

**多臂轮次**：每臂一个子目录 `<臂名>/`，其中必须各有 `SERVE_CMD.txt`、`serve.log`、`serve_args.txt`、`ENV.txt`；轮次根目录放 `round.json`、`batch.sh`、`MANIFEST.sha256`、`round_history/`。臂名只用 `[A-Za-z0-9_]`，例如 `A_cut_on_p1`。

**不需要服务进程的轮次**（纯分析、调研）：免 `SERVE_CMD.txt`/`serve.log`/`serve_args.txt`，在 `round.json` 的 `serve` 字段写 `"none"`。

### 1.3 批次日志

- 批次日志 `batchNN.log` 放在 `/data2/_shared/runs/ft_rounds/` 根目录（沿用 batch5–batch19 的位置），**不放进轮次目录**；在 `round.json` 的 `batch_logs` 字段里引用其绝对路径与 sha256。
- `NN` 取根目录现有最大编号 +1（截至 2026-10-03 21:40 最大为 `batch19`，下一个是 `batch20`）。取号命令：
  ```bash
  ls /data2/_shared/runs/ft_rounds/ | grep -oE '^batch[0-9]+\.log$' | grep -oE '[0-9]+' | sort -n | tail -1
  ```
- 批次脚本本体放 `/data2/FreeToken/runs/plan_batches/batchNN_<轮次ID>.sh`（本地源文件在 `plan/01_测试与调研/batches/`）。

### 1.4 收尾与只读

收尾顺序（不能颠倒）：

1. 写 `round.json`（第一版）。
2. `mkdir round_history && cp round.json round_history/round.v001.json`。
3. 生成清单：
   ```bash
   cd /data2/_shared/runs/ft_rounds/<轮次ID> && \
   find . -type f ! -name MANIFEST.sha256 ! -name round.json ! -path './round_history/*' -print0 \
     | sort -z | xargs -0 sha256sum > MANIFEST.sha256 && \
   (cd round_history && sha256sum round.v*.json > SHA256SUMS)
   ```
4. 只读：`chmod -R a-w /data2/_shared/runs/ft_rounds/<轮次ID>`。
5. 在 `round.json` 里已写 `closed_at`；本地结果文件写明 `MANIFEST.sha256` 自身的 sha256。

**关闭后**：

- 不覆盖、不删除、不改名任何文件。
- 补测：**优先开新轮次**（字母后缀，如 `E1-R008b`），或开新子目录 `supp-<YYYYMMDD>-<n>/`。开子目录只允许对目录本身临时 `chmod u+w <目录>`，建完子目录立即恢复 `chmod a-w <目录>`；子目录有自己的 `MANIFEST.sha256`，并在 `round.json` 里以追加方式登记。
- `round.json` 的后续追加只能通过追加式写入器（开发卡 D04）完成；D04 交付前，执行者**不得修改**已关闭轮次的 `round.json`，有新判定或撤回时写本地结果文件并上报总负责人。

| 类型 | 格式 | 例 | 说明 |
|---|---|---|---|
| 轮次 | `E<代>-R<三位序号>[字母后缀]` | `E1-R008`、`E1-R002b` | 一轮只改一个变量；后缀表示同一问题的复测/补测 |

- `sub_conclusions[].status` 只能取：`kept`、`retracted`、`hypothesis`、`pending`。
- `verdict` 取值：`kept`、`reverted`、`rejected`、`blocked`、`not_met`、`kept_pending_gate`、`measured`（只测量、不改代码的轮次）、`pending_review`（执行者写入时的唯一初值）。
- **执行者只写 `proposed_verdict`，`verdict` 一律写 `pending_review`**；改为正式判定由总负责人通过追加 `verdict_history` 完成。

### 3.2 只追加规则

1. **数值字段一旦写入不得改写**（包括 `results`、`first_shots`、`design`、`base`、`serve`）。发现读错：在 `retractions` 追加一条，再在 `results` 以新键（如 `ttft_cold_s_corrected`）追加，旧键保留。
2. **判定变化**写入 `verdict_history`：
   ```json
   {"time": "2026-10-04 12:00 CST", "old": "pending_review", "new": "kept", "reason": "…", "evidence": ["相对路径或其他轮次ID"], "by": "总负责人"}
   ```
   同时把顶层 `verdict` 改为新值——这是唯一允许改动的已存在字段，且必须与 `verdict_history` 最后一条的 `new` 一致。
3. **解释撤回**写入 `retractions`：`{"time","target"（被撤回的 sub_conclusion id 或文本）,"reason","evidence","by"}`，并把对应 `sub_conclusions[].status` 改为 `retracted`（第二个允许改动的字段）。
4. 每次追加后：新版本另存 `round_history/round.v<NNN>.json`，更新 `round_history/SHA256SUMS`。
5. 写入器（D04）必须检查：旧版本的每个键值在新版本中原样存在（列表只能变长、前缀不变），否则拒绝写入。

## 5. 数据版本（论文用）

### 5.1 发布

- 论文**只引用数据发布版本**。发布 ID：`FTD-<YYYYMMDD>-<n>`（同日第 n 次）。
- 服务器：`/data2/_shared/runs/ft_releases/<发布ID>/manifest.json`（发布后 `chmod -R a-w`）。
- 本地副本：`plan/data_releases/<发布ID>.json`（内容与服务器逐字节相同；两边 sha256 写入本地结果文件）。
- 内容：
  - `release_id`、`created_at`、`created_by`、`paper_version`、`previous_release`；
  - `rounds[]`：轮次 ID、目录、纳入的子结论（含状态）、论文判定与工件内判定、`round.json` 与关键工件的 sha256（取不到写 `"pending_on_server"`）、`MANIFEST.sha256` 的 sha256；
  - `external_sources[]`：如 8098 轮次库文件的 sha256 与读取时间；
  - `changes_since_previous[]`、`errata[]`、`known_discrepancies[]`。
- **发布后不可改**；更正只能发新版本，在新版本的 `errata` 里写明。

### 5.2 引用与论文版本绑定

- 论文引用格式：`〔轮次ID｜FTD-…〕`，例：`〔E1-R003-ckpttax｜FTD-20261003-1〕`。
- 论文版本号与数据版本绑定：
  - 数据新增（新轮次、新子结论、不改变已有结论）→ 论文**次版本 +0.1**；
  - 结论性变化（判定改变、子结论撤回、核心数字更正）→ 论文**主版本 +1**。
- 发布由总负责人决定；服务器侧目录落地可交低成本模型按卡执行。

### 5.3 首个发布

`FTD-20261003-1` ↔ 论文 v4.0，覆盖 v3.2 引用的全部轮次（E0-R000…R009、E1-R000/R000b/R001/R001-64k/R002/R003 及 v2…v5、floor、ckpttax、stateeq，另含 E1-R004）。本地文件 `plan/data_releases/FTD-20261003-1.json`；服务器侧落地见卡 `T01`。

## 6. 执行纪律（GPU 轮次全部适用）

1. **工作树断言**：起服务前断言 `freetoken.__file__ == <WT>/python/freetoken/__init__.py`，且 `git -C <WT> rev-parse --short=7 HEAD` 等于卡片给定 commit，且 `git -C <WT> status --porcelain --untracked-files=no` 为空；`freetoken.kernel._pinned_tensor`、`freetoken.kernel._cpu_moe` 可导入。任一不满足 → 停。
2. **单写者门**：端口无监听、GPU 显存占用 < 1000 MiB、无其他 `ft serve`/`agent_trace.py replay|generate`/`ft_probe*`/`probe_ft_cold32k`/`cold_eq.py`/其他 `batchNN_` 进程（**用 `index($0,self)==0` 排除本脚本自身**，batch19 曾因模式匹配到自己而误判），`/data2/_shared/gpu.lock` 不存在或属于本轮次。每臂起服务前都要过一次门。
3. **GPU 锁**：门通过后写 `gpu.lock`（`{"owner":"<轮次ID>","card":"<卡号>","since":"…","pid":…}`），批次结束（含异常退出，用 `trap`）删除。锁协议与 `/data2/_shared/run_monitor` 一致：**文件存在即表示有人持卡**。发现锁属于别人（包括过期锁）→ 停并上报，**不得自行清除**。
4. **A/B 前跑 `serve_args_diff.py`**：任何对照出数前，`$PY $SCR/serve_args_diff.py A/serve.log B/serve.log` 的差异键必须只有 `pid` 和卡片声明的目标键；多出任何键 → 该对照作废，停并上报（先例：E1-R002 的 `max_extend_tokens` 8192 对 4096）。
5. **因果对照用配对四格**：冷/热 × 开/关。冷格每个样本都是**独立进程重建**（新进程的空缓存），每格 N ≥ 3；同进程连续的热请求不能当独立冷样本。热格与冷格分开报告，不得用合并中位数比较两臂（19:22 撤回的教训，论文 v3.2 §6.4）。
6. **小效应**（预期差 < 10%）：按 ABAB 交替进程顺序，N 由实测波动决定（卡片给出停止规则），报告差值与区间，不只报点值。
7. **首枪单独记录，不丢弃**：每个进程的第一个业务请求单独记入 `first_shots`，不进均值；跨轮比较时它不参与（首枪偏慢 13–16%，论文 §3.3）。
8. **段数取自执行事件**：段数只能数 `serve.log` 的 `Prefill batch, #new-seq: … #new-token: … #cached-token: …` 行或 D0 记录，**不得由 TTFT 反推**（不得用 round(TTFT/2.8)）。
9. **首 token 口径**：只用 `first_real`（首个带内容的增量）；`first_wire`（首个 SSE 事件，空 `role` 增量，约 0.01 s）与 `total`（含 `[DONE]` 后约 3 s 空等）不得当 TTFT。
10. **下载限速**：工作时间 08:00–17:30 任何下载必须 `--max-overall-download-limit=4608K`（4.5 MB/s）；17:30 以后才可全速。
11. **不改代码**：01 执行者不得修改 FreeToken 源码、`freetoken/scripts/` 与远端 `/data2/FreeToken/scripts/` 里的现有脚本、任何 worktree。允许的写入仅限：按模板生成批次脚本、本轮目录、批次日志、`gpu.lock`、本地 `plan/01_测试与调研/results/` 与 `batches/`、卡片明确允许的上传（原样上传本地 `freetoken/scripts/` 中已有脚本并校验 md5）。**T19 例外**：允许在本地仓库根目录下的 `strata\` 与远端 `/data2/Strata/` 下载、构建并写 README，轮次目录为 `X-STRATA-R001`；仍不得修改 Strata 源码。
12. **异常立即停并上报，不自行修复**：门失败、服务起不来、`SERVER_DIED`、OOM、读数与卡片「期望」偏离超过卡片阈值、工件缺失、`serve_args_diff` 多出键、显存停服后未释放——一律停批、清锁、写结果文件「异常」节，不重试超过卡片允许的次数（默认 0 次），不改参数绕过。
13. **生产服务**：不得停止、重启或占用生产 8095 以外进程；若 8095 正由生产服务占用，GPU 卡一律不执行并上报。不得动 ollama（它占用 0、2 号核，论文 §9.1）。
14. **推算先行**：卡片给出的事先推算写入 `round.json.projection`；实测偏离点估计 > 20% 时在结果中标「模型需修正」，不自行改推算。
15. **共用工装修复同步（2026-10-04 用户要求）**：同类工装错误修复后，必须同步到所有共用这段逻辑的运行器，并加原始失败数据的回归夹具。T16 后续门统一复用 `development/t16_candidate_runner_full_tail.py` 与 `t16_full_tail_base_runner.py`；预填事件和 D0 行的期望值从父树臂的实测推出，包含就绪请求，不写死为 12 或 13。尾段覆盖以显式契约记录，不按卡号推断。R019、R021 原始数据作为回归样例；重跑前验证样例、所有使用入口和冻结依赖的源码绑定。历史冻结脚本及失败工件保持只读，仅用于历史复核。

## 9. 代码版本与代（2026-10-03 新增）

1. **代（epoch）**：基础代码换代时开新一代，只在同一代内比较增量。第 1 代的父树分散在 40fd5d4、80943fd、c721c74、97bc62c 四棵树上；**第 2 代统一为 `E2-base`**（构建见 D00）。

3. **round.json**：`base` 字段新增 `code_version`（必填）。`epoch` 与轮次 ID 前缀一致：E2 轮次的 `epoch` 为 2。
4. **数据发布**：发布清单新增 `code_versions`，列出该发布中各轮次用到的全部代码版本。论文的每个数字因此可以追溯为「数据版本 → 轮次 → 代码版本」。
5. **跨代比较**：不同代的数字不直接相减或拼接。需要跨代对照时，开一个轮次在新代上复测旧代的关键点，T00 就是这样的立项轮次。
