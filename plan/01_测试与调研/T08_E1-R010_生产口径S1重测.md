## 口径

- 树：`exp/e1r001b-pr578` @ 80943fd（层优先 + #578），**不设 `FT_DEV_D0`**。
- 启动前缀：`numactl --interleave=all taskset -c 1,3-47`。**不要**再加 `--cpunodebind=0,1`：它会把进程亲和改回全部 CPU，抵消 taskset（两路节点 0、1 就是全部 48 个逻辑核）。避开 0、2 号核，因为它们被常驻的 ollama `llama-server` 占用（论文 §9.1）。
- 参数：生产命令（附录 B）+ `--prefill-layer-major`，`--max-prefill-length 4096`（层优先子块大小取自该参数；E0-R007 证明子块 8192 破坏逐位一致，故保持 4096）。
- 窗口：P1 用生产 49,152；P2 用 73,728（论文 §5.3：49,152 容纳不下 65,412 token 的请求）。`INDEX.md` 第 4 节写的 65,536 放不下 65,412 + 128 输出，本卡不用。

## 判据

测量轮，`proposed_verdict = measured`。必须同时满足才算「生产口径数字可用」：

| 检查 | 条件 |
|---|---|
| taskset 生效 | 两个进程 `GATE-FAIL-TASKSET` 未出现；`ENV.txt`/批次日志有 `1,3-47` |
| 确定性 | `DET BIT_EXACT_MATCH` |
| 稳定性 | 30 分钟内错误数 0 |
| Agent 回放 | 三趟 `dry_run` 计数都为 0 |

对照（只报差值，不判优劣）：冷 32K 与 E1-R001（D0 开、无 taskset）6.49–6.60 s；冷 64K 与 E1-R001-64k 12.43–14.08 s；60 题与历史分数比较时**只与同一判卷器 sha256 的分数比**（9/30 与 10/03 的差异来自判卷器漂移，论文 §9.3）。

## 停止条件

门失败；`GATE-FAIL-TASKSET`；`NOT-READY`；任一 `rc` 非 0（60 题与稳定性子项例外：记录并继续到 `stop`，不重跑）；`cached_tokens` 非 0。

## `round.json` 骨架要点

两份：`E1-R010/round.json`（P1）与 `E1-R010-p64k/round.json`（P2，`parent` = `E1-R010`）。`serve.arms.*.serve_cmd` 必须显示 taskset 前缀；`results` 键：`cold32k_ttft_s`、`decode_tps`、`short_decode_tps`、`det`、`stall_max_gap_s`、`agent_{coldfirst,warm,edit}_{sum,mean,max}_ttft_s`、`quality60_pass_rate`、`evaluator_sha256`、`soak_errors`、`cold64k_ttft_s`；`proposed_verdict` `measured`。
