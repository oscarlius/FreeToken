## 要回答的问题

开启 `--enable-special-token-ckpt` 时，含未缓存锚点的**首次**请求多付约一遍（三组冷配对 +2.6–2.9 s，热格 0；论文 §6.4）。这一遍是否来自 D3 的「预填按锚点切段」，而不是同一开关下的「解码期快照」？做法：保留开关（快照照常），只关切段。

每个进程的 `rep=0 … multi=X` 是**冷格样本**（每进程 1 个，每臂 3 个）；`rep=1..4 … multi=Y` 是**热格样本**（每臂 12 个）。`single=` 是单条消息对照，单独列表。**不得**用 `MEDIAN` 行比较两臂（它混合冷热）。

### 3. 段数（执行事件）


探针发送顺序固定为：rep0 单条、rep0 多条、rep1 单条、rep1 多条……。逐行标注每行属于哪个请求（多条消息请求可能占 1 或 2 行：两行时第二行的 `#cached-token` 等于第一行的 `#cached-token + #new-token`）。

## 判据（执行者据此给「建议判定」）

记 `Δcold = mean(A 冷格 3 个) − mean(B 冷格 3 个)`，`Δhot = mean(A 热格 12 个) − mean(B 热格 12 个)`。

| 结果 | 条件（全部满足） | 建议 |
|---|---|---|
| **支持切段归因** | 2.0 ≤ Δcold ≤ 3.5 s；A 的每个冷请求恰有 1 段 `seg_reason=anchor_cap`、B 的冷请求 `anchor_cap` 段数为 0；A 冷格 3/3 为两段、B 冷格 3/3 为一段；\|Δhot\| ≤ 0.15 s；B 每进程快照次数 ≥ A 对应进程 | `proposed_verdict = kept`；子结论 `E1-R003-ckpttax SC4` 建议 `hypothesis → kept` |
| **否定切段归因** | \|Δcold\| ≤ 0.5 s（无论段数），或 B 冷格为一段但首 token 仍 ≥ 5.0 s | `proposed_verdict = rejected`；建议 SC4 `hypothesis → retracted`，并上报为**结论性变化**（论文 §6.5 第一步的收益假设撤去） |
| **快照退化** | B 任一进程快照次数 < 同序号 A 进程（如 B_p2 对 A_p2），或第二遍 T1 回放中**任一轮** B 的 `cached_tokens` < 同序号 A 进程同一轮 | `proposed_verdict = not_met`（切段可去但快照覆盖退化），上报 |
| 其他 | — | `proposed_verdict = pending_review`，标「不确定」，上报全部读数 |

另报（不参与判定）：第二遍 T1 第 1–11 轮均值与最大值，两臂各 3 个；与推算（A≈3.46、B≈2.71）的偏离百分比，偏离 > 20% 写「模型需修正」。
