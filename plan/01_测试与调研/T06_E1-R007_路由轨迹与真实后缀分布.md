## 要回答的问题

1. **真实后缀分布**：真实循环里（模型输出 + 工具结果作为新后缀），每轮实际 `recomputed_tokens` 的分布。论文 §6.7：T2 相邻提示增量 39–4,897（中位数 330），但提示增量 ≠ 实际重算量。
2. **真实 f(n)**：后缀 n 个 token 时，每层实际用到的专家比例，对照独立均匀假设 `f(n)=1−(1−10/512)^n`（§6.7 表：n=1 2.0%、19 31%、32 47%、64 72%、128 92%、≥256 ≥99%）与无条件界 `[10/512, min(1,10n/512)]`。
3. **R_B**：两路不同内容解码时的专家复用比（§4.3 假设 2；简化模型 B=2 时 R_B≈1.01，不是实测）。
4. **每轮完整输出长度**：检验「每轮输出 > 233 token」这一条件（§4.4 (1)；已知下界：正文前已有约 130–180 个思考 token）。

## 批次脚本（01 README §4 模板）

**参数区**：

**主体区**：

```bash
FLAGS="--prefill-layer-major --max-prefill-length 4096 --enable-special-token-ckpt"
O=$D/G; ok || exit 7
start $O "FT_DEV_ROUTE_TRACE=$O/route FT_DEV_PAUSE_ENDPOINT=1" $FLAGS
[ $READY = 1 ] || { echo "NOT-READY"; stop; exit 6; }
# 1) 三条真实轨迹（不同种子；temp 0；输出预算 2048，比历史 512 更接近真实输出）
for s in seed12k seed_45k seed_real; do
  $PY $WT/scripts/agent_trace.py --route-evidence generate --out $O/trace_$s.json --rounds 12 --max-tokens 2048 --seed-file /data2/FreeToken/wt/e1r003/$s.txt --root /data2/FreeToken/wt/e1r003 > $O/gen_$s.log 2>&1 || { echo "generate FAILED $s"; stop; exit 6; }
done
# 2) 两路不同内容解码（供 R_B）——若 D06 已完成则用其 two-decode；否则跳过并记 pending
TWO_DECODE=()
if [ -f $WT/scripts/multisession_probe.py ]; then
  $PY $WT/scripts/multisession_probe.py two-decode --ctx 8000 --max-tokens 256 --same-prompt 0 --reps 1 --out $O/two_decode.json > $O/two_decode.log 2>&1 || { echo "two-decode FAILED"; stop; exit 6; }
  TWO_DECODE=(--two-decode $O/two_decode.json)
else
  echo "two-decode SKIPPED (D06 未交付); R_B pending"
fi
stop
# 3) 离线分析（不占 GPU）
$PY $WT/scripts/route_analyze.py $O/route --traces $O/trace_seed12k.json $O/trace_seed_45k.json $O/trace_seed_real.json --serve-log $O/serve.log "${TWO_DECODE[@]}" --out $D/route_summary.json > $D/route_summary.log 2>&1 || { echo "analyze FAILED"; exit 6; }
tail -30 $D/route_summary.log
```

当前执行使用 D07 候选树内固定源码工具，不覆盖公共 `$SCR` 中供既有轮次使用的版本。客户端必须显式传 `--route-evidence`；服务器的 route 环境变量不会传给客户端。服务器另需 `FT_DEV_PAUSE_ENDPOINT=1` 以启用真实引擎 UID/ACK，缺失 ACK 则停止。若补充 replay，同样显式传该客户端选项并单列其实际输出预算，不把旧的短回放上限当作 2048 完整输出。

`--two-decode` 将实际 D06 输出、两个 token sidecar、请求 UID 和不同实际输入 token 摘要与同批 decode 路由绑定。未提供该文件时 R_B 为 pending；提供后出现未声明的 B=2 请求组合则分析失败，不能混入其他并发流。

## 读数提取（`route_summary.json` 字段以 D07 约定为准）

| 问题 | 指标 |
|---|---|
| 1 | 每条轨迹每轮 `recomputed_tokens`（n）；全体分布的分位数（min、P25、中位、P75、max）、`n ≤ 64` 的轮数占比 |
| 2 | 对每个后缀：每层实际用到的专家比例的均值与范围；与 f(n) 推算值的差；是否落在 `[10/512, min(1,10n/512)]` 内（**不在界内 → 停，上报为工装缺陷**，因为界是无条件的） |
| 3 | R_B（两路复用比，D07 定义）；跳过时写 pending |
| 4 | 每轮 `completion_tokens`（思考 + 正文 + 工具参数）分布；> 233 的轮数占比；被 2048 截断的轮数（`finish_reason=length`） |

## 判据

测量轮，`proposed_verdict = measured`。子结论（状态先填 `pending`）：

- SC1「真实循环后缀中位数 X token；≤ 64 的轮次占 Y%」→ 供 D13 立项判断（论文 §6.7：真实收益集中在 n 为 1 到几十的情形）。
- SC2「真实 f(n) 相对独立均匀假设偏小/偏大/相符」（按 n 分桶给出）。
- SC3「每轮输出 > 233 token 的轮次占 Z%」→ 若 Z ≥ 50%，写「解码未命中是 PCIe 主要消耗」的**条件成立**（论文 §4.4 (1)）。
- 埋点开时的首 token、耗时**不得**作为性能数引用（写入 `anomalies` 说明）。
