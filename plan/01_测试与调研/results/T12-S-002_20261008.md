## 实际预算路径与单卡校准

`engine.py:_resolve_auto_moe_cache_size` 调用 `cache_budget.resolve_moe_cache_auto`；共同预算为：

```
int(memory_ratio * baseline_free) - weights_bytes
- (QSA fixed bytes + GDN state_pool_bytes)
```

它先保留 KV 页，再优先分给专家槽。`baseline_free` 是 TP rank 的启动前最小空闲；`weights_bytes` 是加载后的实测差；QSA 页成本包含组规格和 pending-ring/scratch；GDN 是 sibling pool。

两份单卡日志的可比输入均为：TP1、`memory_ratio=0.88`、`max_running_req=2`、offload、QSA sparse/hybrid-radix、resolved `page_size=64`、CUDA graph `[1,2]`、启动前空闲 23.11 GiB；48K 的独立 `pLM` 日志重复得到同一几何。不同项是 48K/49,152 reserve 对 64K/73,728 reserve。

| 观测档 | 日志几何 | 预算重放检查 | 结果 |
|---|---:|---:|---|
| 49,152 token | 3,149 槽、768 页、K+V 显示 1.16 GiB | 路由专家文件头 / 24,576 = **2,764,824 B/槽** | 通过 |
| 73,728 reserve（实际页容量 73,792 token） | 2,924 槽、1,153 页、K+V 显示 1.74 GiB | 两档差分给出共同页成本 1,615,806.23 B/page；两档共同池均约 **9.264210 GiB** | 通过 |

差分为：`(3149-2924)*2,764,824 = (1153-768)*1,615,806.23`。按此页成本，768/1,153 页为 1.1557/1.7351 GiB，落在日志显示的 1.16/1.74 GiB 两位小数舍入区间。64K 日志实际分配 73,792 而目标 reserve 为 73,728，差 64 token、0.0868%，低于 ±3%。

这纠正旧报告的表述：其“0%”不能只说来自反推回代；文件头槽字节和两份独立日志几何可以交叉检查。它仍不等同于在当前 `e2base1` 工作树实际启动一次服务。

## TP 规则与边界

| 类别 | TP2 / TP4 规则 | 证据等级 |
|---|---|---|
| 路由专家缓存 | 若 bank 真按 rank 均分，每槽为 TP1 的 1/2、1/4 | `expert_bytes_per_slot` 求已分片 bank 的本 rank 行字节；Qwen 路径尚未实现，故为推断。 |
| 全注意力/KV | 2 KV heads：TP2 可各 1；TP4 必须每头复制到两 rank 或采用另一未实现布局 | 模型配置可读；TP4 规则为推断。 |
| GDN state | key 16、value 48 可除以 2/4；`linear_state_pool` 的 local dims 用 `div_even(...allow_replicate=True)` | 组件规则有源码；Qwen TP 端到端仍未实现。 |
| QSA indexer、超连接 | 当前模块使用 replicated linear，按 rank 复制 | 源码支持。 |
| PLE | 47.745 GiB 表留 pinned host/UVA；每 token 16×160 = 2,560 B 特征读入 staging | 源码支持；无 TP 分支，不能假定“一卡读后广播”。 |
| embed/lm_head | 通用 `VocabParallelEmbedding` 按 `ceil(vocab/tp_size)` 分片 | 组件能力；尚未接入 Qwen TP loader。 |

`models/qwen4_exp/weight.py:206-207` 仍明确：`qwen4_exp weight loading supports TP=1 only`。这使预测不能转化为容量承诺；它不是 T12 的 GPU 前置。

## 三种负载与 TP4 95% 敏感性

| 卡片负载 | 单卡已校准数据 | TP2 | TP4 |
|---|---:|---:|---:|
| 1 路 48K | 3,149 / 24,576 = 12.81% | 无实现，不能报实测槽数 | 无实现，不能报实测槽数 |
| 2 路 64K | 无对应启动/并发几何 | 无实现，缺每-rank KV/GDN/graph 预算 | 同左 |
| 8 路 32K | 无对应启动/并发几何 | 无实现，缺每-rank KV/GDN/graph 预算 | 同左 |

若专家 bank 真均匀 TP4 分片、总槽数仍 24,576、kernel 没有更低 slot cap，95% = 23,348 槽需要每 rank **15.029 GiB** 专家槽预算（100% 为 15.820 GiB）。这还没有扣 TP4 KV 复制、复制的非专家权重、QSA/GDN 固定项、CUDA graph/activation 和分配器余量。

因此 `>=95%` 对专家是否 1/4 分片、KV 复制布局、实测每-rank `baseline_free/weights_bytes`、并发形状和 graph 余量一阶敏感。T12 允许 TP 推断，但现有证据不足以诚实地产出 1×48K、2×64K、8×32K 的具体 TP2/TP4 槽数。

## 给 D13 的建议与停止条件

先做 TP2：实现并验证 bank 分片、KV/GDN local geometry 与非专家权重加载；再做 TP4 的两 KV-head 复制/布局。TP2 的真实启动结果应成为 TP4 预算输入。T12 到此停止；继续补精确多卡数字需要 D13 已实现的 TP 加载路径或另开 GPU 测量卡，均不属于本只读任务。
