## 0. 结论

1. **方向基本正确，但要换一个说法。**
   - H0「以专家流遍数作为成本单位」在物理上成立，实测证据很干净。
   - 但「预填按遍计成本」这个现象，伯克利原文 §2.1 和 §5.3 已经写过。第 2 版把它当作自己的发现，这一处必须改成「继承原文，研究其后果」。
2. **H0 直接作用于首 token 和停顿；多路速度和冷 64K 不是它已证明的收益。**〔v3.1 修订〕
   - 首 token 在两条单会话轨迹上已低于 10 s。
   - 停顿在第 1 代没有实测，第 0 代为 16.69 s，**未达标**。原文「已达标」有误，已撤回。
   - 多路速度：PCIe 预算只是必要条件，不排除两路每路 30 tok/s。可能的路径有 CPU 补带宽，或者错相位重叠解码（D14）。
   - 冷 64K：只靠 MoE 提速需要接近或超过 BF16 峰值，实践上要先压非 MoE。
   - 第 2 版没有说清这一点。终稿新增第 4.4–4.6 节，给出了定量界。
3. **按读码结果，H0 的四个机制里有两个上游已部分存在。**
   - 「同一时刻多请求共用一遍」上游已有。
   - 「遍内取单个状态快照」上游已有单点版本。
   - 「第二遍」是我们自己的 D3 引入的回退。
   - 真正新的只有：遍内插解码（D6，代价最高）、多锚点快照、短后缀按需搬运（适用面窄），以及本文的预算和排队分析。
4. **基线口径要诚实**：
   - 「冷 32K 21.5 → 6.5 s」用的是 4096 分块基线；相对已调优的生产 8192 分块（约 13.0 s）约为 2 倍。
   - 其中 13.8 → 6.5 s 来自未合并的上游 #578，按归因规则不计入本文贡献。
   - 终稿摘要已按这个口径改写。
5. **定位建议**：第一阶段手稿按「测量与建模报告」投 workshop 或 experience 类稿件可以成立。要冲系统顶会，至少还需要 D6 实现，加上 S2 的多会话达标率实测，或者多卡结果。
6. **GPT-6 两份稿**：
   - 8 项 arXiv 引用全部真实，标题和作者都已核实。
   - 方法论（归因规则、强基线、不制造瓶颈、配对实验、留出验证）照单采用。
   - 问题依旧是 `REVIEW_GPT6_DIRECTION` 指出的四处：数字过时、H1 作核心不对、多卡没算显存账、TP 数值门执行不了。这四处终稿都已吸收。

## 3. 对服务器新数据的解读（RESULTS_E1 之后）

1. **臂 D（层优先、0 槽）**：倒序真冷趟 0/12 轮命中，合计 126.39 s；臂 C（层优先、32 槽）5/12 轮命中，合计 83.61 s。按 RESULTS_E1 事先写好的判据，**#577 的 host bank 在层优先下生效，D3 应基于 #577 来改**，只需自写触发点。这个判定可以写进 E1-R004。
2. **2.8–2.9 s 地板的归因与 `RESULTS_E1` 第 6 条不同。**
   - `RESULTS_E1` 的说法：每请求固定开销，不是预填，随消息条数增长；层优先冷 32K 的 6.5 s 里约 2.8 s 是它。
   - 本评审的结论：地板就是「每个请求至少一遍专家流」。依据有四条：
     1. `scheduler/cache.py:96` 至少留 1 个 token 要预填；`layers/moe.py:347-384` 对任何长度都整层搬运。
     2. 地板值与 $P/B_P=2.80$ s、D0 每遍 2.86 s 吻合。
     3. 分块模式下 20,000 字符（两块）为 5.79–5.80 s，正好两遍；层优先下同一请求为 3.05–3.10 s。固定开销不会随块数翻倍。
     4. D0 中短段计算 2.2 ms、整段 2.79 s、搬运 57.7–63.5 GiB。
   - 「随消息条数增长」由锚点切段完整解释（见下一条）。
   - 推论：层优先冷启受计算限制，这一遍搬运与计算重叠，**不能**在 6.5 s 里扣掉 2.8 s。
   - 最终裁定：从现有工件看一个 `recomputed=1` 请求的 D0 每遍 H2D 字节，是否约为 63 GiB。
3. **第二档来自锚点切段：开关探针已经支持。**〔E1-R003-floor，E1–E4〕
   - 12 条消息：开时 5.43 / 5.73 s，关时 2.80 / 2.90 s。
   - 分块模式带 tools 冷提示：8.65 对 5.76 s。
   - 单条消息时两档几乎相同。
   - 这组对照关掉的是整个开关；只关切段、保留快照的 E1-R008 仍要做。
4. **噪声地板已补齐**〔E1-R003-v5，A2/B2〕：
   - 首 token 合计差为 +2.0% 和 +0.12%。
   - 正文口径假失败 3/12 和 4/12，即每轮 25–33%。
   - 恢复对重算的 1/12 低于这个地板。输出层门不可用，这一点坐实了。

**hybrid 1.8 GB/s 的解释**：每层交给 CPU 的只有约 6.7 MB，多出的 3.75 ms 由固定延迟主导。读码看到每个任务有 2 次自旋屏障；线程绑在 0..22 号核，其中 0、2 号核被 ollama 占用。自旋屏障一旦等到被抢占的线程，就要等一个调度时间片（毫秒级），与观测同一量级。这是推断，需要 E1-R002b 验证。

E1-R002b 建议增设变体 C：专家池 `--membind` 到 node1。这是一个待验证的假设。$B_H$ 按原文是实测的专家处理带宽，不能用「STREAM 减去 PCIe」直接推出可行性。

**读码代理有一处错误，已纠正**：它估算 D13 时用了 E=256、k=8，本模型实际是 E=512、k=10。终稿用的是正确参数。
