# D15 development expert-cache policy

The runtime stays on `FT_DEV_EXPERT_POLICY=lru` unless explicitly enabled.  The modes are exact: `lru` is disabled-by-default and preserves the existing LRU path; `profile` preloads a supplied profile; `profile+adapt` is only armed until the engine supplies a decode-boundary proof.  The D15 offline tool reads the D07 trace contract: each `route-*.npz` contains `expert_ids` shaped `[moe_layer, token, 10]`; the matching JSON sidecar remains provenance data and is not rewritten.

Run `python tools/build_expert_profile.py ROUTE_DIR PROFILE.strp --num-experts E` to emit the `STRP` format used by Strata.  The layout reference is Strata's `tools/make_profile.py`, Copyright (c) Strata contributors, MIT License.  No Strata GGUF or GPU kernel is included or used.

Set `FT_DEV_EXPERT_POLICY=profile` and `FT_DEV_EXPERT_PROFILE=PROFILE.strp` to preload ranked experts.  With prefill overlap, slots `[0, 2E)` are reserved for the volatile double buffers, so the profile always starts at `2E`.  The code records profile hits, misses and replacement bytes.  `profile+adapt` stays fail-closed until the scheduler-owned `RuntimeAdaptationCoordinator` has stopped launch, drained the actual completion and copy streams, and issued a proof bound to scheduler identity, launch generation, cache/device, mapping generation, boundary sequence and private key.

`FT_DEV_EXPERT_ADAPT_LAG1=1` is default-off.  It freezes a plan at boundary N, excludes all stable slots referenced by N's raw top-k routes, copies each replacement to private staging on an auxiliary copy stream, and does not change `slot_for_id`, `id_of_slot`, or a live cache row at N.  At a later boundary the cache first observes that transaction's completion event; an incomplete event leaves the old map and blocks a second pending transaction.  Only a complete event permits staged rows and mappings to publish.  The transaction keeps per-swap D0 receipts (step, boundary, layer, expert, slot, byte count, enqueue-start, enqueue-finish, observed completion time, and publication time) in `${FT_DEV_D0_PATH:-/tmp/ft_dev_d0}_adaptation.jsonl`.  Enqueue and observed completion are deliberately distinct fields.

CUDA publication still requires the existing scheduler-owned runtime proof.  CPU fixtures model the protocol with controllable test-completion events; those events do not represent GPU completion and do not prove CUDA stream ordering or token equivalence.  A failed publication restores rows and both mapping directions; a failed rollback locks only the opt-in policy.

When adaptation promotes an expert that is currently owned by a volatile prefill slot, publication clears that volatile slot's reverse owner before assigning the stable slot.  Both directions are verified before mutation; inconsistent ownership fails the transaction and restores the map/weight snapshot.  This prevents later prefill-buffer invalidation from turning the promoted expert into a false cache miss.  It establishes residency bookkeeping only, not token divergence or GPU correctness.

T06 supplies the real `seed12k` profile and parameter selection.  GPU/default-path equivalence remains gated by R041, and D15 admission plus T21 remain deferred until T06 and the queued GPU gates; this document makes no performance claim.
